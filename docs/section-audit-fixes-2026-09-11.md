# Исправления CRM, расчётов, чата, профиля и рейтинга

11 сентября 2026. Дополнение к `audit-fixes-2026-09-11.md`.

## Изменения

- CRM и отчёты используют один обработчик черновика расчётов. GET возвращает `calculationDraftVersion`; сохранение требует эту версию и атомарно сравнивает исходную запись. Неактуальная версия → 409, ошибка чтения/записи или повреждённый JSON → 503. Группы cash/winloss/figures сохраняют остальные поля. Клиент передаёт версию и показывает конфликт, сохраняя локальную копию ввода. Неопределённая запись не повторяется автоматически через второй endpoint. Старое открытое приложение без версии необходимо обновить.
- Карточка CRM и состояние рассылки больше не игнорируют ошибки записи. Обработка и управление одной задачей рассылки получают Redis-lock. Каждый получатель имеет отдельную запись доставки: сохранённый результат воспроизводится без отправки; неопределённая доставка блокирует повтор. Ответ Telegram rate_limited освобождает запись для безопасного повтора. Запись доставки хранится 7 дней, задача — 2 часа. Нельзя обещать exactly-once через внешнюю API при сетевом обрыве: неоднозначный результат требует проверки, автоматической повторной отправки нет.
- Размер страницы чата 40 больше не используется для LTRIM истории — включая системные сообщения рейтинга/газеты и групп. Новые сообщения не дублируются полным JSON в бесконечно растущий индекс. Поиск сообщения при редактировании/удалении читает страницы по 40 вместо всей истории. Исправлены beforeTime и запасной курсор при исчезнувшем beforeId. Обычный опрос по-прежнему читает короткий хвост; глубокая загрузка старой истории пока использует существующий полный диапазон.
- Комментарий и его requestId сохраняются одной Lua-операцией, исключающей «успешный повтор» без записи. Ошибки возвращаются явно. Потерянный ответ после записи безопасно повторяется с тем же requestId. Другой текст с тем же ID → 409. Уведомление запускается только при первой записи.
- Админское уведомление рейтинга принимает общую Telegram/PWA-аутентификацию; обычный пользователь по-прежнему получает 403.
- Исправлена запись Evgen1722 за Bali Yana 28.06.2026: points 60 → 0. На исходном `assets/rating-compressed-preview/rating-28-06-2026-league1-bali-yana-20k-08h.avif` указаны 5-е место, ITM=3 и −0.3; опубликованные правила исключают отрицательный результат. Остальные 14 предупреждений strict-валидатора не пересчитывались: среди них старые ручные исключения и объединённые турниры. Без первичных подтверждений менять исторические начисления нельзя.
- Кэш PWA v59 предлагает обновление штатной кнопкой, без принудительной перезагрузки с потерей ввода.

## Старая история чата

Уже обрезанные сообщения не появляются автоматически: они могут сохраниться только в старом индексе. Он намеренно не удалён. Есть инструмент восстановления **одного явно указанного диалога**:

```sh
node scripts/recover-chat-history.js --thread poker_app:chat:1001_1002
node scripts/recover-chat-history.js --thread poker_app:chat:1001_1002 --apply --backup /secure/path/chat-backup.json
```

По умолчанию — только проверка. Для применения обязательна новая резервная копия (права 0600, проверка прочитанных байтов). Lua сравнивает исходную историю и индекс перед заменой: при одновременном сообщении/редактировании восстановление прекращается без перезаписи. Индекс удаляется только вместе с успешным восстановлением. Ограничения 10 000 записей истории и 32 MiB защищают от непроверенного массового переноса. Сохранённые копии могут содержать персональные данные — резервную копию хранить вне репозитория.

На production восстановление не запускалось: в окружении нет доступа к рабочему Redis. Сначала проверка и восстановление нужных диалогов, затем ранее подготовленная миграция приватных вложений. Сами старые публичные файлы этим изменением не закрываются.

## Проверки

- 75 контрактных сценариев: включают общую аутентификацию, админские права, сохранение групп расчётов, чат send/edit/delete, 61 сообщение без обрезания, 20 старых сообщений на следующей странице, PWA-уведомление, параллельную обработку одной рассылки и pause/resume.
- 264 unit-теста прошли.
- `scripts/test-section-integrity.js` на настоящем временном Redis: конкурентные/устаревшие черновики, отказы GET/SET, повреждённый JSON, параллельные комментарии и потерянный ответ, повтор доставки и неопределённый результат, захват задачи, временные курсоры, резервное копирование/восстановление истории и конкурентное сообщение во время восстановления.
- Синтаксис JS/CSS и сборка прошли. Браузерные navigation/admin и chat flows прошли на тестовых API. PWA upgrade проверяется отдельно штатным `scripts/test-pwa-update.js`.
- `npm run smoke` по-прежнему сообщает только о ранее существовавших превышениях бюджетов HTML/eager scripts и размера ресурсов. Пороги не повышались. Strict-рейтинг: 14 исторических предупреждений; это не зелёная проверка данных.

Этот пакет исправляет воспроизведённые проблемы из дополнительного аудита. Отдельная многозаписная ветка синхронизации рейкбек-черновика с отправленными отчётами не переводилась в транзакцию; отмеченный при чтении кода риск требует отдельной проверки. Боевые балансы, реальные рассылки и выплаты в тестах не использовались.
