# Источники и пути лидов

Раздел «Ссылки»: поля источника, размещения, кампании, объявления и стартового экрана. Старые JSON-параметры и ссылки совместимы. Кнопка «Пути лидов» открывает постоянную историю; прежний ограниченный журнал оставлен отдельно.

## Правила

- Первый источник — первая **записанная tracking-ссылка**, а не доказательство первого знакомства человека с клубом. Последний источник хранится отдельно. Источники берутся только из существующих ссылок.
- Источник сохраняется на сервере по installation ID и затем по аккаунту из проверенной авторизации. Прямой возврат авторизованного пользователя с другого устройства использует его контекст.
- Первоначальный гость и связанный аккаунт объединяются при чтении. Контекст другого аккаунта на общем устройстве не переносится. После выхода на уже связанном устройстве анонимные события не приписываются прежнему аккаунту; сбор для аккаунта продолжается после авторизации.
- Метки нового/существующего аккаунта основаны на доступной дате регистрации (включая старый Telegram alias). Неизвестная дата показывается явно.
- Депозиты читаются из CRM-журнала аккаунта и его старого alias, без двойного учёта одинакового ID операции. Учитываются только положительные конечные суммы с датой не раньше первого источника. Сумма и конверсия относятся к первому источнику; повторное рекламное касание не присваивает ту же выручку.
- Суммы CRM отображаются в рублях, как в существующей CRM. Это депозиты из журнала, а не подтверждение платежа от банка. Журнал ограничен последними 200 событиями на ID; отсутствие записи не доказывает отсутствие депозита. Историческую сумму за всё время эти данные не гарантируют.
- Сводка вычисляется для загруженных посетителей (по 50), что явно указано в интерфейсе. История действий загружается порциями HSCAN и сортируется среди уже загруженных событий.

## Хранение

`poker_app:attribution:v1:`: contexts (первый/последний источник), owners (подтверждённая связь установки с аккаунтом), installations:<account> (установки аккаунта), members:<ref> (посетители ссылки), touches (первое касание ссылки в сессии), events:<actor> (история с уникальным event ID).

Запись контекста и событий выполняется через существующий guarded atomicWrite с повтором при конфликте. Повторная отправка event ID не дублирует историю. Клиент повторяет временно неуспешный запрос с тем же ID. Для нового хранилища нет усечения до 25 событий; чтение порционное. Старые истории не восстанавливаются задним числом. Удаление ссылки прекращает новые касания по её коду; уже записанная атрибуция остаётся историей аккаунта.

История содержит существующие аналитические события, разделы и подтверждённые даты регистрации/привязки из серверных полей, а также операции CRM. Тексты чатов и содержимое полей не собираются.

## Выгрузки

Импорт отдельного файла депозитов пока не добавлен: формат не предоставлен. Для него нужны игровой ID (и клуб, если ID уникален только внутри клуба), дата, сумма, валюта, тип операции и стабильный ID транзакции. Импорт должен сначала показывать сопоставления и неоднозначности, а затем идемпотентно записывать операции в долговременный журнал. Нельзя считать общий недельный итог отдельными платежами или угадывать игрока по нику.
