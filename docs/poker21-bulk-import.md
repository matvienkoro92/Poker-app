## Что реализовано

`python3 scripts/import-poker21-json.py SOURCE --db LOCAL_DB --mode cash --session SESSION_ID --expected HANDS --player PLAYER_ID --projection LOCAL_JS`

Импорт читает сразу весь файл, проверяет формат NLH, карты, завершение и единственный большой блайнд, сохраняет персональные проекции в SQLite. Повторная загрузка не удваивает данные. Конфликтующие версии одной раздачи исключаются до разбора; неизвестные форматы и неоднозначные блайнды попадают в журнал отказов. Экспорт для просмотра содержит только явно выбранного игрока. ## Что ещё не автоматизировано

Штатная кнопка 数据导出 существует в журнале раздач. Во встроенном браузере её нажатие не дало доступного нового файла. Доступ к серверному API выдачи полных историй и способ скачивания без интерактивной сессии не подтверждены. В уже реализованной интеграции проекта есть сводная статистика, кассовые операции, турниры и текущие столы; готового метода истории карт там не найдено. Это не доказательство отсутствия такого метода у поставщика.

Рабочий следующий этап — получить полные выгрузки нужных сессий и загружать их этим импортёром. Для автоматического обновления клуба нужен документированный серверный экспорт либо надёжный механизм скачивания. Не хранить браузерные cookies в коде приложения.

## Готовый запрос поставщику (не отправлен)

Нужен read-only доступ к JSON-истории раздач нашего клуба: первоначальная выгрузка за период и последующие изменения. Сейчас ручной экспорт Poker21Plus.json содержит Id, RecordId, UserIdN, ScoreN, base_data.card и base_data.opt. Просим описать endpoint, авторизацию, фильтры клуба/лиги/периода, пагинацию, ограничения частоты, маркер завершения сессии, исправления ранее выданных записей, точные денежные единицы и включение рейка/страховки/джекпотов. Нужны карты всех выданных стартовых рук, включая фолды, и различение cash/MTT/SNG. Важны контрольное количество раздач и возможность повторной выгрузки без пропусков.

После подтверждения канала: серверный загрузчик → очередь импорта → база раздач → агрегаты по игроку/режиму/руке/периоду. Личный API должен выбирать игрока по привязанному аккаунту, не доверять playerId от клиента. SQLite сейчас — локальный проверочный этап, не выбранное хранилище для всего клуба.
