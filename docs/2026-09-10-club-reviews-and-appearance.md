# Разборы и оформление профиля

## Разборы

На главной — «Разборы с тренером и игроками». Два вида публикаций: вопрос и раздача. Для раздачи можно добавить ситуацию, один скриншот и скрытый под раскрывающимся блоком исход. Автор выбирает обращение к тренеру и игрокам или только к игрокам. Все вошедшие участники могут отвечать, включая ответы на конкретный комментарий. Ответы тренера выделены и стоят первыми. Для раздач есть голосование пас / колл / рейз, результаты видны после выбора; это мнение участников, не оценка правильности.

Тренер — Николай FishKopcheny. Сервер находит канонический ID по индексу привязанного Poker21, проверяет привязку и серверный nickname и сохраняет ID в `poker_app:reviews:coach_account` через SET NX. Отображаемое имя и поля тела запроса не дают роль тренера. После закрепления переименование никнейма не передаёт права другому аккаунту. Если привязка ещё не обнаружена, сервер не назначает роль произвольному пользователю. Реальная запись роли не создавалась в ходе локальных тестов.

Автор подписан на ответы; другие участники могут подписаться явно. Пуши используют существующие пользовательские настройки доставки. Вопрос тренеру уведомляет тренера; ответ — подписчиков, кроме самого отвечающего. Ссылка `?startapp=review_<id>` ведёт прямо в обсуждение. Сводка показывает ссылки на обсуждения с новыми ответами. Прочтение отмечается после показа конкретной версии, не после открытия списка.

API `/api/club-reviews`, POST. Авторизация и канонический ID получаются на сервере. Запрещены гости и заблокированные пользователи. Создание и ответы идемпотентны по accountId + requestId. Изменения темы выполняются CAS через Redis EVAL с повтором при конфликте: параллельные ответы не затираются. Удалять могут автор и администратор; удалённый ответ перестаёт отображаться. Максимум 150 ответов / 100 подписчиков / 1000 голосов на обсуждение. Списки — по 20, есть пагинация. Автор не может задавать чужой ID или роль тренера. Скриншот сжимается клиентом и проверяется сервером; внешние URL и SVG не принимаются.

## Оформление

В собственном профиле кнопка «Оформить профиль»: предпросмотр, 5 вариантов рамки включая отсутствие рамки и одна заработанная турнирная ачивка на витрине. Изменения сохраняются на сервере и отображаются в собственном профиле и карточке игрока, открытой другим участником. Арты личных героев остаются за их владельцами; смена аватара — существующим способом. Рамки в строках общего чата в эту версию не входят.

Серверный каталог доступных наград генерируется вместе с клубными новостями в `lib/profile-achievement-catalog.json` из опубликованных результатов. Доступны «Король турниров», «Герой дня», «Миллионер клуба», «Занос от 50 до 100к», «Занос от 100к». Клиент не может прислать произвольную награду. Сохранение всегда в аккаунт из авторизации, поле targetId игнорируется при записи. Выбор не хранится только на устройстве.

## Проверки

`node --test tests/club-social.test.js tests/friend-news.test.js tests/friend-news-api.test.js` — проверки прав, авторизации, роли, идемпотентности, параллельных ответов, отметок прочтения, приватности списков подписчиков/голосов и доступности наград.

`output/club-social-check/browser.cjs` — полная локальная страница приложения с подставными API: создание раздачи и загрузка изображения, скрытый исход, голосование, черновик, повтор отправки после ошибки, тренер первым, push-ссылка, сохранение/повторное открытие оформления, очистка при выходе. Стартовая заставка скрыта только в тесте: подставные API не завершают реальную авторизацию.

В ходе тестов публикации, комментарии и пуши реальным участникам не отправлялись. Изменения пока локальные.
