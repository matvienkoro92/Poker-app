# Статистика своих tracking-ссылок

Категории, персональные доступы, общая сводка и матрица игроков доступны только во вкладке «Свои». Автоматические CRM-рассылки исключены на сервере и в интерфейсе; для них остаётся отклик на сообщение (журнал переходов и навигации). Рассылка не создаёт и не перезаписывает первый источник привлечения. Существующая история своих источников восстанавливается из сохранённых событий, без изменений записей Redis.

Переходы и посетители берутся из журнала hit и множества посетителей ссылки. «Всего открытий и нажатий» — отдельный журнал навигации (загрузка раздела, нажатие перехода); это не сумма круток, розыгрышей и других аналитических действий. Повторные открытия не равны уникальным людям.

«Активные посетители» — посетители, открывшие минимум два разных раздела после перехода по ссылке. Карточки считают разные `view:*` из сохранённого журнала навигации; общая сводка — разные `section_opened` той же ссылки в выбранном периоде. Повтор одного раздела, `open:*`, `landing:*`, неизвестные разделы и одни бизнес-действия не выполняют этот критерий. Варианты написания раздела с дефисом и подчёркиванием считаются одним разделом. История пересчитывается при чтении, запись или миграция Redis не нужна. Пояснение по «?» описывает этот же критерий.

Подробная история и матрица игроков строятся по durable attribution events. События другой ссылки исключаются, повторы одного event ID не увеличивают итоги. Одно участие в конкретном розыгрыше считается один раз для игрока, независимо от устройства. Пропущенный referral event не заменяется выдуманным переходом.

Аккаунты объединяются только по сохранённым проверенным связям visitor_dt_ids и account_redirects. Регистрация и привязка Poker21 читают как числовые timestamp, так и ISO-даты. Уровень берётся из того же memberProfile, что используется в приложении.

Депозиты: подтверждённый журнал `poker21:admin-deposits:v1`, фактический плательщик (не получатель вывода), точный Poker21 ID и подтверждённые владельцем связи румов. Копейки переводятся в рубли. Учитываются части платежа, исключаются отмены, бонусы, переводы, выплаты владельцем и Эксчип-выводы. Ручные отметки CRM не суммируются с платёжками: иначе один депозит можно посчитать дважды. Доход относится к первому подтверждённому источнику; платежи до перехода исключаются. Без подтверждённой привязки ID либо при недоступности журнала показывается неизвестное значение.

Членство в Telegram-чате проверяется только для группы, соответствующей приглашению с главной. Нельзя подставлять канал или другую группу уведомлений. Сводка и матрица используют одну проверку/кеш членства. Ошибка API или неизвестная группа не превращаются в «Нет». Подписка на бота берётся из доверенных webhook-событий и сохранённых подписок; это последнее подтверждённое состояние, а не проверка отправкой сообщения.

Старые анонимные переходы без цепочки attribution невозможно достоверно связать с игроками задним числом. Показывается покрытие подробной историей; неизвестные бизнес-показатели не подменяются нулём. Старый журнал переходов сохраняется.

## Проверка существующих данных

`node scripts/audit-tracking-links.cjs --corrected` читает только свои ссылки и все страницы их игроков. Скрипт запрещает Redis-команды записи и любые внешние запросы кроме настроенного Redis, а одинаковые чтения кеширует в рамках одного запуска. Результаты сохраняются локально в `output/tracking-audit-2026-10-22/`; они содержат идентификаторы игроков и не предназначены для публичного размещения.
