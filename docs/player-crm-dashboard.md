# Player CRM / Dashboard

Актуальное состояние CRM после майской сборки 2026-05-04.

## Назначение

Раздел начинался как CRM по потоку игроков, но сейчас по факту работает как операционный дашборд клуба: быстро показывает базу, регистрации, Poker21, подписки, чаты, депозиты, график прироста и списки людей по клику.

CRM не должна придумывать данные. Если у показателя нет надежного источника, он не выводится как факт.

## Аудит сбора данных - 2026-05-08

Этот аудит был сделан до последующей работы по админским отчетам/рейкбеку и не является свежим TODO. Он фиксирует, как читать CRM именно как дашборд сбора данных.

- Основные карточки CRM тогда уже покрывали периодные показатели: база, регистрации, Poker21, новые bot/push подписки, депозиты, чатовые метрики и дневной график.
- Для управленческого дашборда полезно держать рядом два типа чисел:
  - прирост за период: новые регистрации, новые подписки, депозиты за выбранный период;
  - состояние сейчас: всего в базе, всего зарегистрировано, всего достижимы в bot/push, активные 7/30 дней.
- Для рассылок нужен полный funnel: `sent`, `delivered`, `opened`, `clicked`. На момент аудита отправка и касания кампаний уже сохранялись, а отдельная запись push-click/open требовала доработки через service worker/API-событие.
- Критичный риск, который тогда нужно было проверять первым: сбор визитов должен стабильно писать события, потому что от него зависят `Посещения`, `Пользователи`, дневной график и новые пользователи.
- Инвариант после аудита: не добавлять красивые карточки без честного источника данных; лучше показывать меньше метрик, но с понятной природой числа.

## Периоды

Верхний период управляет сводными карточками CRM и чата.

Доступные варианты:

- `7 дней`
- `30 дней`
- `90 дней`
- `Текущая неделя` - с понедельника по сегодня
- `Прошлая неделя`
- `Текущий месяц`
- `Прошлый месяц`
- `За все время`
- `Даты` - ручной выбор через календарь

При смене периода интерфейс показывает загрузку и затем перерисовывает данные.

## Главные карточки

В верхнем блоке CRM выводятся показатели за выбранный период:

- `Игроков в базе`
- `Зарегано`
- `Poker21` - привязали аккаунт
- `Новые подписки на бот`
- `Новые push-подписки`
- `Депозиты`

Карточки сделаны кликабельными там, где за ними есть список.

### Зарегано

Карточка `Зарегано` разбита на мини-показатели:

- `Только Telegram` - есть Telegram-логин/бот, но нет email.
- `Только Email` - есть email, но нет Telegram-логина/бота.
- `И то и то` - есть и Telegram, и email.

По клику открывается модалка со списком. Сначала показывается 15 человек, затем есть кнопка `Показать всех` и кнопка выгрузки.

### Poker21

Показывает игроков, которые привязали аккаунт Poker21. По клику открывается список. В отдельном разделе Poker21 есть фильтры по уровню и дате привязки.

Уровень Poker21 считается на сервере из данных профиля Poker21 через `pokerStatusLevelFromFee`.

### Новые подписки

`Новые подписки на бот` и `Новые push-подписки` кликабельны и открывают списки людей за выбранный период.

Периодные карточки подписок считают только события с датой:

- `botSubscribedAt` для подписок на бота;
- `pushSubscribedAt` для push-подписок.

Текущее состояние `channels.bot` / `channels.push` используется для сегментов и достижимости, но не подменяет историческую статистику. Если у старой подписки нет сохраненной даты, CRM не должна задним числом раскладывать ее по дням.

## Чат

Чатовые показатели вынесены в отдельный блок `Чат` и визуально отделены от CRM.

Показатели:

- `Сообщений в главном чате` - всего / за выбранный период.
- `Личных диалогов` - всего / за выбранный период.
- `Групповых чатов` - всего / за выбранный период.
- `Диалогов у Ани` - всего / за выбранный период.
- `Диалогов у Вики` - всего / за выбранный период.
- `Все остальные диалоги` - все диалоги, которые не относятся к Ане и Вике.

По клику на `Сообщений в главном чате` открывается модалка с топом авторов по количеству сообщений за выбранный период. Сначала выводится топ-10, затем можно раскрыть всех.

По клику на диалоги менеджера открывается модалка со списком диалогов. По клику на конкретный диалог в списке показывается сама переписка в этой же модалке.

В модалках есть собственный выбор периода, чтобы смотреть список не только по текущему периоду страницы.

## График

Раздел `Обзор` заменен на `График`.

График показывает прирост по датам. Период графика выбирается отдельно от общего периода CRM.

Доступны те же варианты периода:

- 7/30/90 дней
- текущая неделя
- прошлая неделя
- текущий месяц
- прошлый месяц
- за все время
- ручные даты через календарь

Под графиком есть галочки серий. Если галочка выключена, линия не отображается. Если все галочки выключены, линий нет.

Серии:

- `Игроков в базе`
- `Регистрации`
- `Poker21`
- `Новые подписки на бот`
- `Новые push-подписки`
- `Депозиты`
- `CRM сообщения`
- `Сообщения в чате`

Если у серии нет датированного источника, она не должна рисоваться как дневной прирост.

При наведении на график показываются значения за дату и вертикальная пунктирная линия через всю область графика.

Под графиком выводится сводка прироста по датам, чтобы было видно, в какой день какой показатель вырос.

## Игроки

Раздел `Игроки` показывает список игроков порциями по 15 человек. Есть кнопка `Показать всех`.

Карточка игрока не висит постоянно на странице. Она открывается отдельным окном по клику на игрока.

Удалены неподтвержденные или лишние поля:

- статус;
- `не играл 999 дней`;
- фейковый счетчик игр;
- `пора написать`;
- `без депозита в CRM`;
- `депозит без игры`;
- `турнирные по тегам`.

Количество игр сейчас не считается, потому что надежного источника игр в CRM нет. Раньше это могло означать только число импортированных или вручную записанных событий типа `game`; без такого импорта показатель не выводится.

## Mobile PWA Layout

CRM открывается как portaled full-screen view: `#playerCrmView` переносится в `body`, чтобы не зависеть от ограничений карточки приложения и нижней навигации.

Текущий layout-инвариант:

- `#playerCrmView` - fixed full-screen flex shell;
- back-button - отдельный верхний flex item;
- `.player-crm` - единственный scrollport контента;
- `.admin-section-views` скрыт внутри CRM, потому что служебная строка просмотров не должна занимать высоту portaled-экрана;
- `styles.css` обязан cache-bust-ить внутренние CSS imports той же версией, что и HTML/JS, иначе PWA может получить новый router/CRM JS со старым `styles-layout.css`.

Этот инвариант закрывает мобильный регресс, где на iOS/PWA вместо статистики оставалась только стрелка назад или пустая темная область.
