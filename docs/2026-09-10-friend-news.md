# Новости друзей и совместные призовые места

## Исправления

- Турнирная история для ачивок и новостей теперь включает сентябрь. Сезонная таблица и итоги лета по-прежнему используют только июнь–август.
- Лента больше не принимает три случайных аватара из превью профиля за полный список друзей. Новый авторизованный `/api/friend-news` получает полный канонический список через тот же слой, что основной список друзей.
- Для истории и непрочитанного используются данные аккаунта. Поддерживаются Telegram/email, старые связи друзей мигрируются существующим механизмом.
- Личные кэши новостей разделены по аккаунтам. Удалённые друзья отфильтровываются из старых сгенерированных событий. Успешный пустой ответ не заменяется старой лентой.
- Обновление при авторизации слушает фактически используемое событие `poker-telegram-auth`, а не только старое `poker-auth-changed`. Поздний ответ предыдущего запроса не заменяет ленту после смены аккаунта.

## Совместный результат

Событие создаётся для пары друзей только при наличии положительных призовых и места у обоих в одном турнире. Идентичность турнира включает дату, время, название и индекс внутри дневного источника. Совпадения по одному дню недостаточно. Дневные агрегаты не используются.

Генератор клубных новостей сохраняет подтверждённые турнирные строки за последние 60 дней данных в `lib/friend-tournament-results.json`. Сервер формирует персональные совместные события из этого файла и текущих друзей; клиентские суммы и результаты не принимаются. Карточки добавлены в новости друзей и историю профиля участника.

Проверочный случай из исходных данных: 9 сентября 2026, Big Boss — ПокерМанки, 1-е место, 73 198,45 ₽; Waaar, 3-е место, 9 768,75 ₽. Обычная новость Waaar и общая карточка присутствуют независимо друг от друга.

## Непрочитанные новости

Красная точка ставится на навигацию профиля, вкладку друзей, кнопку списка друзей и вход в новости друзей. Само открытие профиля не снимает точку. Карточки считаются просмотренными, когда видимы в открытой ленте друзей; общие новости клуба не помечают персональную ленту прочитанной.

`POST /api/friend-news`:

- `action: feed` возвращает канонический аккаунт, полный список друзей, совместные события и прочитанные ID.
- `action: read, ids: [...]` добавляет прочитанные ID только для авторизованного аккаунта. Переданный клиентом accountId не определяет владельца отметок.

Хранилище: Redis Set `poker_app:friend_news_read:<accountId>`, срок 120 дней после записи. Записи объединяются, а не заменяются: чтение на двух устройствах не затирает друг друга. При отсутствии сети отметки не подтверждаются сервером и точка восстанавливается.

## Пуши

`/api/cron-friend-news` запускается на 23-й минуте каждого часа и требует Bearer `CRON_SECRET`. Он отправляет участникам совместных результатов за последние три дня персональный Web Push через существующий `sendToMemberDevices`; пользовательские настройки отключения пушей сохраняются. Ссылка открывает новости друзей (`startapp=friend_news`).

Ключ дедупликации включает конкретный турнир и отсортированную пару аккаунтов. Повторный запуск не повторяет уже доставленное событие. Общий механизм отправки освобождает ключ после полного сбоя доставки. Исторические события старше трёх дней доступны в ленте без ретроспективной рассылки. При первом запуске на сервере возможна отправка ещё не отправленных совместных событий за последние три дня.

Сборка только генерирует данные; новые персональные пуши отправляет серверный cron после публикации. В локальной проверке реальные уведомления не отправлялись.

## Проверки

- Новые тесты: реальная пара ПокерМанки/Waaar, разные турниры в один день, нулевые призовые/места, отсутствующие и неоднозначные аккаунты, явные алиасы, повторные строки, срок истории, полный список вместо превью, разделение кэшей, точки и просмотр карточек, авторизация отметок, Redis-ошибки, секрет cron и ключи повторной доставки.
- Chromium, экран 390×844, настоящая разметка профиля и модуль новостей, изолированные ответы API: точки до чтения, общая карточка, обычная новость Waaar, запись двух просмотренных событий, отсутствие ошибок JavaScript. Снимки находятся в `output/friend-news-check/`.
- Полная сборка и проверка синтаксиса прошли. Все 14 новых тестов прошли. Общий набор: 184 успешных из 188 до добавления двух последних регрессионных проверок.
- В общих тестах обнаружены существовавшие до изменения сбои: `home-leaderboard-banner.test.js`, проверка названия ачивки Poker21 в `tournament-bet.test.js`, две проверки артов в `sng-notification-banner.test.js`, контракт `testDailyPokerLevelPayout` (`DEVICE_REQUIRED`). Они воспроизведены с исходными версиями изменённых файлов из HEAD без отката рабочего дерева.

Состояние опубликованного приложения, реальная связь аккаунтов в Redis и доставка на физические устройства в этом локальном прогоне не проверялись. Причины пропуска установлены по коду, а результат воспроизведён на реальных локальных турнирных данных с тестовым списком друзей.

## Исправление начального счётчика

Первая загрузка новой версии создаёт постоянную серверную границу `poker_app:friend_news_tracking_since:<accountId>` через SET NX. История до этой границы остаётся в ленте, но не считается новыми уведомлениями: отсутствие старых отметок чтения не доказывает непрочитанность. Граница общая для устройств и не сдвигается при обновлении. До получения границы клиент не показывает счётчик. Это начало нового учёта уведомлений, а не восстановление неизвестной истории чтения.
