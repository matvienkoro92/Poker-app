# Poker21 profile and admin rakeback worklog - 2026-05-20

Этот документ фиксирует закрытый слой правок от 20 мая 2026: новую статистику Poker21 в профиле, точные периоды по датам, стабилизацию рейкбек-таблицы, шаблоны, итоги и отправленные отчеты.

Это уже сделанная работа, а не список задач.

## Коротко

- В профиль Poker21 выведены новые поля статистики из `today_counter`, `week_counter`, `total_counter`.
- Нулевые значения статистики больше не прячутся.
- `mtt_round` и `sng_round` убраны из профиля, потому что это не то же самое, что количество сыгранных турниров.
- Для статистики Poker21 сделаны вкладки `Сегодня`, `Неделя`, `Всего`, `Период`.
- `Период` открывает один календарь, где можно выбрать диапазон от одной даты до другой.
- Календарь Poker21 показывает кликабельными только даты, по которым у нас есть точный дневной снимок статистики.
- Для рейкбека добавлены цвета строк, копирование ID, строгие проверки сохранения, подтверждение удаления и устойчивое поведение шаблонов.
- Итоги рейкбека снова открываются по клику и показывают `рейк / рейкбек`, в том числе по датам.
- В отправленных отчетах ускорено первое открытие и добавлены новые итоговые блоки.

## Poker21 stats in profile

Poker21 передает счетчики:

- `total_counter`;
- `today_counter`;
- `week_counter`.

Backend нормализует эти счетчики в `lib/pokerplus.js`, frontend рисует их в `app-profile-pokerplus.js`.

В профиле показываются:

- `fee` как `Рейк`;
- `hands` как `Хендс`;
- `winnings` как `Кеш`;
- `mtt_winnings` как `MTT`;
- `mtt_count` как `MTT игр`;
- `mtt_itm_count` как `MTT ITM`;
- `mtt_1st_count` как `MTT 1-е`;
- `sng_winnings` как `SNG`;
- `sng_count` как `SNG игр`;
- `sng_itm_count` как `SNG ITM`;
- `sng_1st_count` как `SNG 1-е`.

Нулевые значения выводятся явно. Это важно для полей вроде `mtt_count`, `mtt_itm_count`, `sng_count`, где `0` тоже является полезным ответом от Poker21.

Поля, которые нормализуются, но не выводятся в профиль:

- `mtt_round`;
- `sng_round`;
- `bb`;
- `ofc_winnings`.

`mtt_round` и `sng_round` убраны после уточнения, что пользователю нужны именно игры/турниры (`mtt_count`, `sng_count`), ITM и первые места, а не внутренние раунды.

## Poker21 period tabs and exact date ranges

Вместо трех больших блоков статистики сделаны четыре вкладки:

- `Сегодня`;
- `Неделя`;
- `Всего`;
- `Период`.

Вкладка `Период` открывает один календарь. Первый клик выбирает начало диапазона, второй клик выбирает конец. Если выбран один день, период считается как один день.

Календарь не дает выбрать даты без точных данных. Это сделано намеренно: если по дате нет дневного снимка, интерфейс не должен показывать "точную" статистику, которой на самом деле нет.

## Poker21 daily snapshots

Для точных периодов backend сохраняет дневные снимки Poker21-статистики в Redis:

```text
poker_app:pokerplus_profile_snapshots:<accountId>
```

Формат ключа описан в `docs/redis-schema.md`.

Каждая запись хранится как `YYYY-MM-DD -> JSON`. Дата снимка считается по Москве (`Europe/Moscow`) в `lib/pokerplus.js`.

Важное ограничение: точный период работает только с датами, которые уже были сохранены нашим приложением как дневные снимки. Если игрок подключился только сегодня, прошлые дни не появятся автоматически задним числом, если Poker21 не отдаст нам отдельную историческую дневную статистику.

Сегодняшний `today_counter` может участвовать в периоде как текущая доступная дата.

## Admin rakeback rows

Во вкладке `Рейкбек` закрыты следующие правила:

- клик по полю `Айди` копирует ID игрока;
- пустую запись нельзя сохранить;
- строку нельзя сохранить без процента;
- строку нельзя сохранить, если нет данных для расчета рейкбека;
- отрицательные значения запрещены во всех числовых полях;
- несохраненные строки не участвуют в итогах;
- при удалении строки показывается подтверждение;
- кнопки строк остаются рабочими во время фонового сохранения, чтобы интерфейс не выглядел зависшим;
- цвет строки сохраняется и не пропадает после сохранения/перерисовки;
- у шаблонов тоже есть кнопка выбора цвета.

Для фишечных румов в заголовках явно указано, что `Рейк` и `РБ` вводятся в фишках:

- `Хпокер`;
- `Супрема`;
- `PPpoker`.

При общем сравнении по всем румам фишечные значения по-прежнему пересчитываются через множители рума.

## Rakeback templates

Шаблонные строки получили отдельное поведение:

- если в шаблоне ввести только процент без рейка, это не создает рабочую запись и не поднимает шаблон наверх;
- такой процент сохраняется как дефолт для шаблона;
- после ввода процент сохраняется автоматически, без нажатия на галочку;
- сохраненное поле процента визуально становится "зафиксированным";
- цвет шаблона тоже может быть закреплен за шаблоном;
- повторный статус `Шаблоны загружены` больше не должен появляться при каждом сохранении;
- поиск по ID ищет и по скрытым шаблонам;
- скрытые шаблоны не рендерятся все сразу, чтобы не возвращать долгую загрузку.

Инвариант: поиск может раскрыть нужный шаблон, но закрытый список шаблонов не должен заранее рисовать все 165 строк.

## Rakeback addons and dates

Для связанных доп. строк рейкбека закреплены правила:

- доп. строка ставится сразу после строки/доп. строки, от которой она создана;
- цепочка доп. строк сохраняет порядок;
- расчет доп. строки идет от дельты к предыдущему рейку в группе;
- удаление защищено от ломания цепочки: нельзя удалить середину так, чтобы остались зависшие последующие доп. строки;
- дата записи отображается бейджем рядом с номером/ID;
- дата записи выбирается через календарный input;
- новая дата для рейкбек-записей переключается по cutoff `12:00 МСК`.
