# Мобильная загрузка и безопасность инструментов сборки

## Зависимости

Полный npm audit после установки: **0 уязвимостей**, включая devDependencies. Обновлён sharp до 0.35.4. Для @capacitor/assets заданы overrides на общий исправленный sharp и tar 7.5.22; xcode использует uuid 11.1.1. Корневой Capacitor CLI разрешился в 8.5.1. Версии зафиксированы package-lock.json.

Исправление uuid подтверждено [релизом разработчика](https://github.com/uuidjs/uuid/releases/tag/v11.1.1); сведения о sharp — в [истории выпусков](https://sharp.pixelplumbing.com/changelog/).

Добавлен npm run check:build-tools, который проверяет реальные операции через зависимости инструментов: генерацию 12 Android-иконок, чтение изображений, создание идентификатора xcode, упаковку и распаковку tar. Проверка проходит. Она включена в CI; Node в CI обновлён с 20 до 24, поскольку Capacitor CLI требует Node >=22.

cap sync android проходит. Полная сборка APK не проверена: в окружении отсутствует Java Runtime. Рабочие ресурсы Android не перегенерировались: проверка иконок использует временный проект.

## Что изменено в мобильном старте

- Убрана автоматическая очередь загрузки HTML, CSS и JS почти всех разделов после старта. Она остаётся доступной только через явный флаг __pokerAllowProgressiveViewHydration. Загрузка при переходе и по намерению пользователя сохранена.
- Для текущего экрана стили запрашиваются явно. Обязательные стили главной страницы и турниров включены в начальную загрузку: они больше не меняют геометрию после первого показа.
- Сборка добавляет preload импортируемых CSS. Границы файлов и порядок каскада сохраняются: старые CSS-фрагменты местами зависят от восстановления синтаксиса браузером на конце файла, поэтому их простое объединение небезопасно.
- Блок новостей присутствует в начальном HTML, его высота и размеры слайдов зарезервированы заранее.
- Анимация блика основной кнопки использует transform вместо изменения left.
- Основное изображение получило AVIF 77 497 байт вместо WebP 171 200 байт; WebP оставлен как fallback в picture. Разрешение и прозрачность сохранены.
- У окна ставки повышена специфичность правила видимости: поздняя загрузка общих модальных стилей больше не скрывает его.

Статический бюджет CSS изменён с 700 до 760 KiB, фактически 756,1 KiB: он теперь включает обязательные стили главной, прежде загружавшиеся позднее. Это перенос существующей работы в правильную фазу загрузки. Лимиты передачи, JS и общего public не увеличены. Статический стартовый набор около 898 KiB; фактический сетевой трафик включает динамические ресурсы и измеряется отдельно.

## Проверки

Мобильный сценарий: Chromium, 390×844, DPR 2, touch, CPU ×4, сеть 1,6 Мбит/с, задержка 100 мс. API подменены тестовыми ответами; это не физический телефон и не замер production. Тест теперь ждёт обязательные стили главной перед итоговым снимком. Дополнительно проверяется, что окно ставки остаётся видимым после загрузки общих модальных стилей.

Первый итоговый прогон: FCP 2,60 с, LCP 3,02 с, сумма сдвигов 0,00062, DOMContentLoaded 7,89 с. Для сравнения, предыдущий зафиксированный итог до этой работы: 3,61 с, 4,58 с, 0,167 и 10,83 с соответственно. Числа отдельных запусков зависят от нагрузки машины; одновременно со первым прогоном выполнялись проверки сборки. Оформление проверено по снимку экрана.

Модульные и контрактные тесты, smoke, расширенная навигация и визуальные проверки запускаются через npm run release:check. Тест навигации теперь дожидается загрузки обработчиков окна игроков после показа его загрузочной оболочки; раньше они случайно успевали загрузиться фоновой очередью.

Не выполнялись публикация, git push и отправка сообщений пользователям.

Повторный итоговый мобильный прогон: FCP 2,61 с, LCP 3,14 с, сумма сдвигов 0,00062, DOMContentLoaded 7,28 с; 112 ресурсов и 1400,7 KiB передачи до точки замера. Все пять сценариев прошли, включая позднюю загрузку общих стилей поверх открытого окна ставки. Время длинных задач остаётся заметным (718 мс превышения порога 50 мс); оптимизация выполнения JS может быть следующим отдельным этапом.

Итог проверки: сборка, синтаксис, 97 smoke-проверок, бюджеты, API-контракты и 64 модульных теста прошли. После уточнения ожиданий теста отдельно успешно повторены расширенная административная навигация и визуальные проверки. В навигационном тесте Promise загрузки удерживается в состоянии окна и проверяется через waitForFunction: это устраняет ошибку Playwright «Resulting promise was garbage collected» при холодном открытии рейтинга, не меняя код рейтинга.
