# Статистика стартовых рук: первый этап

Локальный прототип: `output/hand-statistics-preview/index.html`. Общий вычислительный модуль: `lib/hand-statistics.js`. В production-навигацию и API пока не подключён. Начальное состояние пустое; учебная выборка включается только кнопкой и явно обозначена. Реальных личных записей в файлах прототипа нет.

169 классов обычного NLH: пары, suited и offsuit. Кеш, MTT и SNG изолированы. PLO, short deck, bomb pot и другие варианты не должны нормализоваться как NLH.

## Контракт данных

Каждая строка — одна завершённая раздача одного подтверждённого игрока:

- `source`, `sessionId`, `handId`, `playerId`: строковые идентификаторы; составной ключ исключает повторы.
- `mode`: cash / mtt / sng; `game`: NLH.
- `playedAt`: валидное время UTC в ISO-формате с Z; интервалы from включительно / to исключительно.
- `cards`: ровно две различные карты из A,K,Q,J,T,9…2 и c,d,h,s; только собственные карты игрока.
- `status: completed`, `verified: true`: результаты предварительной серверной сверки.
- `unit`: RUB для кеша, CHIP для MTT/SNG; `scale: 100`.
- `resultMinor`: целое знаковое число в сотых долях единицы; ноль допустим, null/строки не допустимы.
- `bigBlindMinor`: положительное целое в тех же единицах, именно блайнд этой раздачи.
- `netDefinition: game-net-v1`: результат игры после рейка в кеше, без депозитов/выводов, рейкбека, страховки, JP и внешних корректировок; в турнире — результат в турнирных фишках без денежного бай-ина/выплаты.

`verified` не является авторизацией и не может приниматься на доверии из браузера. Будущий API должен сам определить playerId из подтверждённой привязки dtId, отфильтровать собственные раздачи и проверить источник. Pure-модуль не подключается к административному интерфейсу. Нельзя передавать ему произвольный сырой Win как resultMinor. Рубли нельзя назначать источнику до подтверждения единицы.

Учитываются все выданные стартовые руки, включая фолды, обязательные блайнды/анте, нулевые результаты. Выборка только шоудаунов или прибыльных эпизодов не подходит. Неизвестные карты и расчёты исключаются с причиной; в интерфейсе реального источника нужно показывать охват и число исключений.

Сумма bb = сумма resultMinor / bigBlindMinor по каждой раздаче. bb/100 = 100 × сумма bb / число учтённых раздач. Суммарные фишки разных уровней MTT не выражают денежную прибыль или ICM EV. При анализе MTT рекомендуем отдельно показывать структуру по глубине стека на следующем этапе; результат большой руки на поздней стадии может доминировать в сумме фишек.

Меньше 100 наблюдений одной руки помечается как маленькая выборка. Это интерфейсная подсказка, а не доказанная граница статистической достоверности; отсутствие метки также не означает надёжную оценку. Никакой GTO/EV-оценки модуль не делает.

Повтор одинаковой записи пропускается. Конфликт двух валидных версий одного ключа исключает этот ключ целиком до серверного разрешения. Неизвестные поля не приводятся к нулю. Пустые ячейки возвращают null; известная безубыточная выборка возвращает 0.

## Следующий этап

1. Получить проверенный read-only экспорт для одного добровольно выбранного аккаунта: все выданные руки за короткий период, включая фолды.
2. Подтвердить семантику результата, комиссии, блайндов, формата и UTC. Сверить суммы с известными итогами; выявленные в исследовании некорректные сводные Win не использовать.
3. Написать серверный адаптер с каноническим dtId и только личной проекцией. Ни IP, ни карты оппонентов в клиент не выдавать.
4. Добавить авторизованный экран профиля, полноту периода, неизвестные записи, состояния ошибки/загрузки и очистку при смене аккаунта.
5. Отдельно проверить дедупликацию, права доступа и отсутствие влияния на рейтинг/выплаты перед публикацией.

Проверка вычислений: `node --test tests/hand-statistics.test.js`. Прототип не требует сборки приложения и не изменяет текущие игровые результаты.

## Позиции (сентябрь 2026)

В рабочем экране starting-hands добавлены независимые фильтры позиции для cash/mtt/sng и таблица результата по позициям выбранного формата/периода. Матрица и список рук учитывают позицию; таблица позиций остаётся полной для сравнения. Пока поддерживается NLH, как и исходная матрица.

Поле position формируется импортёром из порядка занятых мест base_data.UserIds при единственных соседних SB/BB. HU выделяется как BTN/SB. При нескольких постах блайндов, неполном составе или неоднозначности — UNKNOWN. На коротких столах названия назначаются от поздних позиций (4-max: CO/BTN/SB/BB). До 10 мест; UTG+3 используется для 10-max. Старые записи без позиции остаются в общей статистике и группе «Не определена».

Локальное обогащение старой проекции: scripts/backfill-hand-positions.py. Оно не загружает данные на сервер; публикация кода и обновление хранилища выполняются отдельно.

Поиск ID раздачи и соперника применяется при каждом input, совместно с форматом, датой и позицией. При активном поиске список показывает совпадения по всем стартовым рукам, а не только выбранной ячейке матрицы. Ники соперников сопоставляются по части строки с нормализацией регистра/символов, транслитерацией и вариантами раскладки из поиска игроков. Личная проекция содержит только ID/имена соперников; их карты и технические данные не добавляются. Скрипт build-poker21-replays.py обогащает staged-список участников; требуется обновление серверной проекции вместе с публикацией экрана.

## График результата

Накопительный график по всем прошедшим фильтры раздачам: красная — результат игрока без вскрытия (включая его фолды), синяя — со вскрытием, зелёная — сумма. Игрок, сбросивший до чужого вскрытия, относится к красной линии. Завершённая доска с минимум двумя не сбросившими игроками подтверждает вскрытие для этих игроков. Неполные сведения дают showdown=null; при таких записях красная/синяя линии включают только классифицированные результаты, зелёная — все; показываются предупреждение и неклассифицированная сумма. График всегда накопительный: при выборе bb/100 в матрице график остаётся в bb. MTT — результат фишек/BB, не денежный турнирный профит.
