# Первые четыре пункта аудита: реализация

Обновление: оставшиеся предупреждения зависимостей и мобильная загрузка доработаны в следующем этапе. Актуальные результаты — [мобильная загрузка и зависимости](2026-09-05-mobile-dependencies.md). Ниже сохранён отчёт первого этапа.

Изменения выполнены локально 5 сентября 2026 года. Публикация и git push не выполнялись. Существующие пользовательские изменения сохранены.

## 1. Авторизация

Проверка Telegram Mini App initData сведена к общему валидатору: подпись, положительный безопасный числовой ID, обязательный auth_date, возраст не более 24 часов и допуск будущего времени 60 секунд. Telegram Login также отклоняет некорректное будущее время.

VK-идентичность не получает Telegram-права администратора по совпадению числового ID или username. Полные административные права определяются актуальными списками Telegram ID / подтверждённого email; старые флаги сессии и username сами по себе их не предоставляют. Существующая специальная роль редактора бонусов сохранена, но закрыта для VK.

Email/PWA-коды генерируются через crypto.randomInt. Ограничения хранятся в Redis и действуют между экземплярами приложения: на аккаунт 3 отправки за 10 минут и 10 попыток проверки/входа за 15 минут; на IP — соответственно 20 и 60. Превышение возвращает 429 и Retry-After, недоступность Redis — 503. Лимит тела запроса 16 KiB.

Ограничение: общая система отзыва ранее выданных PWA-сессий не добавлялась; их существующий срок жизни не менялся.

## 2. Бонусный учёт

Redis pipeline проверяет каждую команду и полноту ответа. Ошибки чтения баланса не превращаются в нулевой баланс. Изменение баланса, журнала и агрегатов выполняется одним Lua-скриптом с проверкой владельца блокировки и исходного баланса. Перед записью проверяются типы ключей и целочисленные счётчики: Redis Lua сам по себе не откатывает записи при ошибке выполнения.

Daily Poker сохраняет состояние игры, начисление, билеты и ответ для повторного запроса атомарно. Освобождение блокировки использует сравнение токена и удаление в одном скрипте. Восстановление общего остатка не перезаписывает уже созданный конкурентной операцией итог.

Добавлен test:redis с настоящим локальным Redis: конкурирующие начисления, общий итог разных пользователей, просроченная блокировка, неверные типы ключей и счётчики, недостаток средств, изменение исходного баланса, ограничения входа и отказ Redis. Тест работает в изолированном процессе без подключения к рабочей базе. CI устанавливает Redis и запускает этот тест.

Ограничение: это не нагрузочное испытание рабочего Upstash и не гарантия сохранности при инфраструктурной потере данных Redis; резервное копирование остаётся отдельной задачей эксплуатации.

## 3. Проверки и расчёты

Календарные контракты получили фиксированные часы и возможность CONTRACT_TEST_NOW. Дополнительно проверены границы месяца/года. Хрупкие проверки текста заменены проверкой поведения там, где важен результат открытия deep link.

Найден и исправлен реальный дефект рейкбека: при обратном порядке подзаписей сумма на экране могла отличаться от сохраняемой. Предыдущая сумма теперь определяется по времени записей, а не по порядку DOM. Убрано повторное открытие отчёта через дублирующий обработчик кнопки.

Полный release:check прошёл: сборка, синтаксис, 97 smoke-проверок, бюджеты, API-контракты, 64 модульных теста, расширенная административная навигация и визуальные сценарии. После финальных точечных изменений повторены затронутые контракты, тесты окна ставки и синтаксис.

## 4. Стартовая загрузка

SNG загружается при обращении к соответствующему сценарию. Окно ставки ждёт базовые и собственные стили перед показом. Удалена спекулятивная фоновая загрузка нескольких разделов; загрузка по намерению пользователя сохранена.

Галерея использует небольшие WebP-превью вместо крупных исходных стикеров. 222 JPEG-превью рейтинга заменены ссылками на AVIF; оригиналы сохранены. Данные турниров, очки и распределение по лигам не изменялись. Сборка минимизирует пробелы JS/CSS через esbuild, сохраняя имена и исходные файлы.

Бюджет текущего сезона явно скорректирован с 28 до 36 MiB: приложение относит к нему четыре месяца (июнь–сентябрь), а не три. Общий лимит public 105 MiB и остальные лимиты не повышались. Отчёт учитывает минифицированные файлы public и CSS-импорты.

measure:mobile запускает сборку в Chromium 390×844, DPR 2, touch, CPU ×4, сеть 1,6 Мбит/с с задержкой 100 мс. Проверяет гостевой старт, видимость окна ставки после загрузки CSS, SNG и deep link. Отчёт и снимки записываются в tmp/mobile-startup. API подменены: это воспроизводимый лабораторный сценарий, не измерение реального телефона или рабочего сервера.

## Остаточные ограничения

npm audit --omit=dev не обнаружил уязвимостей production-зависимостей. После совместимых обновлений в инструментах разработки остаётся 7 предупреждений (3 moderate, 3 high, 1 critical), преимущественно в цепочке Capacitor/assets. Принудительные несовместимые обновления не выполнялись; отдельно требуется проверить обновление Android-инструментов.

## Итоговый мобильный замер

FCP 3,61 с, LCP 4,58 с, CLS 0,167, DOMContentLoaded 10,83 с; 131 ресурс и 2334,4 KiB фактической передачи до точки замера. Все четыре сценария прошли, ошибок JavaScript нет.

Предварительный прогон до финальной минификации показывал LCP 3,50 с и CLS 0,104: временные метрики не улучшились в этих единичных запусках. Снижение статического объёма подтверждено, ускорение на реальных устройствах пока не доказано. Следующий этап производительности — стабильность геометрии первого экрана и сокращение цепочки запуска скриптов.
