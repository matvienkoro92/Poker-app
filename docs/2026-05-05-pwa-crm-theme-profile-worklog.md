# PWA / CRM / Profile / Night Theme Worklog - 2026-05-05

Этот документ фиксирует закрытый блок быстрых пользовательских правок от 2026-05-05. Он намеренно стоит как историческая запись: после этого уже были отдельные работы по Poker21 binding/debug, admin reports, rakeback, spring rating data и chat keyboard baseline.

## Scope

- Chat/PWA: desktop PWA composer после отправки не должен сам подниматься.
- Hall of Fame / уровни: рыбка и уровень должны соответствовать реальному Poker21 level, строки игроков должны открывать профиль.
- Profile / Poker21: без прочитанного Poker21-профиля не показывать фейковый уровень `1`.
- CRM: периоды 7/30 дней не должны давать одинаковые карточки из-за неверной агрегации; подписки должны читаться как события за выбранный период.
- UI: кнопки уважения, night theme, download/cashout/home blocks и активная нижняя навигация должны соответствовать выбранной теме.

## Closed Fixes

### Desktop PWA Composer

- Закрыто поведение, когда desktop PWA chat composer поднимался после отправки сообщения.
- Отправка текста, emoji-only или смешанного сообщения не должна сама переводить composer в lifted/focused state.
- Composer поднимается только от явного пользовательского focus/touch на поле ввода.

### Levels / Fish / Profile Clicks

- В модалке `Игроки по уровню` уровень выводится в одну строку с суффиксом `ур.`.
- Рыбка/аватар уровня берется по реальному Poker21 level, а не по дефолтному состоянию.
- Каждая строка игрока в рейтинге уровней кликабельна и открывает профиль игрока.
- Открытие профиля из модалки уровней не должно закрывать родительскую модалку и оставлять на экране только профиль.

### Poker21 Profile State

- Если API не прислал реальный `level` от Poker21-профиля, блок уровня и рыбка не показываются.
- Для такого состояния используется пользовательский текст: `Обновите свой уровень во вкладке Профиль Poker21`.
- Сообщение `Данные Poker21 обновлены.` выводится над кнопкой обновления, а не в случайном месте карточки.
- В статистике Poker21 на этом этапе отрицательный выигрыш не выводился как положительный/полезный показатель. Более поздняя работа 2026-05-08 отдельно пересмотрела поведение отображения отрицательных значений; см. `2026-05-08-poker21-debug-summary.md`.

### CRM Period Stats

- Исправлена логика, из-за которой выбор `7 дней` и `30 дней` мог выглядеть одинаково для CRM-карточек.
- Карточки игроков, регистраций, Poker21, депозитов, bot и push теперь опираются на выбранный период и датированные источники.
- Для bot/push зафиксирован смысл показателя: это новые подписки за выбранный период, если у события есть `botSubscribedAt` / `pushSubscribedAt`.
- Текущий сегмент `Подписан на бот` остается текущим состоянием игрока, но периодная карточка CRM больше не выдает current-state за историческую статистику.
- Старые подписки без сохраненной даты нельзя честно разнести по периодам задним числом; они не должны подмешиваться в дневной прирост как факт.

### Mobile PWA CRM Shell

- Закрыт регресс мобильного PWA, где в CRM мог остаться только back-button или черная пустая область вместо статистики.
- Причина была комплексной: `#playerCrmView` portaled в `body`, конфликтовал с fixed/scroll правилами `.player-crm`, а PWA мог держать старый `styles-layout.css` из-за устаревших импортов в `styles.css`.
- `#playerCrmView` закреплен как full-screen flex shell, а `.player-crm` стал единственным внутренним scrollport для CRM-контента.
- Back-button оставлен отдельным fixed-shell элементом сверху и больше не вытесняет статистику из видимой области.
- Служебный блок `.admin-section-views`, который автоматически добавляется в `.view`, скрыт внутри CRM, чтобы он не занимал flex-высоту и не появлялся внизу portaled-экрана.
- CSS cache-bust выровнен с app version: внутренние импорты `styles.css` больше не должны оставаться на старом `?v=2.685`, когда HTML/JS уже обновлены.
- Финальная мобильная проверка на viewport `393x852` подтвердила, что `playerCrmStats` рендерит `.player-crm__stats-grid`, точка в верхней части экрана попадает в stats grid, а CRM API вызывается с PWA-сессией владельца.

### Profile Controls

- Кнопки `Поднять уважение` и `Уменьшить уважение` выровнены в одну строку там, где им хватает ширины.
- Touch/click зоны сохранены рабочими после lazy hydration.

### Night Theme

- Уменьшено количество синего в night theme на главном экране и в rating/promo блоках.
- Активная кнопка `Главная` в нижней навигации night theme приведена к оранжевому состоянию, как остальные активные кнопки, вместо отдельного золотого варианта.
- Кнопка с рыбкой около рейтингового блока адаптирована под night theme: темная графитовая поверхность, оранжево-золотой акцент и без dark-gold чужого фона.
- Home tournament/freeroll блок адаптирован под night theme: меньше синего, больше графита и теплых акцентов.
- Download/Poker room блок адаптирован под night theme, чтобы карточки Poker21/XPoker/PPPoker/SupremaPoker не выглядели взятыми из темно-золотой темы.
- Cashout/deposit block адаптирован под night theme: зеленые CTA и зеленоватые панели заменены на оранжево-графитовую схему.

## Data Contract Notes

- CRM не должна придумывать историю там, где нет timestamp.
- `channels.bot` может означать текущую достижимость игрока через бота, но периодная статистика считает только строки с `botSubscribedAt`.
- `channels.push` аналогично считается за период только по `pushSubscribedAt`.
- UI должен называть такие карточки `Новые подписки на бот` и `Новые push-подписки`, чтобы не смешивать их с текущими сегментами.
