# Telegram Chat Summary — 2026-04-19

## Зачем этот файл

Короткий итог по работам вокруг Telegram-чата за цикл 2026-04-19.

Здесь оставлено только главное: что меняли, что нашли, что важно не повторять.

## Что делали

В этом цикле правили три связанные зоны:

- список чатов и клики по аватарке;
- нижнюю линию под `Викой` в списке;
- Telegram chat composer, который поднимался и прыгал при открытии клавиатуры.

## Что реально сделали

В коде зафиксированы такие группы изменений:

- вернули разделитель под `Викой`, как у остальных контактов;
- клик по аватарке в списке чатов теперь открывает диалог, а не превью аватарки;
- унифицировали safe-area и внешние отступы у chat composer;
- несколько раз чистили Telegram-specific layout и keyboard overrides;
- убрали старые Telegram keyboard/dock/root-lock/fallback ветки, которые конфликтовали с общей chat-логикой;
- добавили жёсткий guard, который в Telegram-чате сбрасывает composer state к дефолту и не даёт включать отдельные lift-сценарии.

## Главный инженерный вывод

Проблема была не в одной строке CSS и не в одном обработчике `focus`.

Composer могли поднимать сразу несколько независимых путей:

- `chat-keyboard-open`;
- fixed composer lift в общем PWA path;
- `updateChatMessagesKeyboardPad()`;
- `syncPwaChatVisualViewportInset()`;
- `applyChatThreadComposerKeyboardDockFromCover()`;
- старые Telegram-specific CSS overrides;
- прямые fallback-обработчики, которые вручную включали keyboard-mode;
- Telegram root-lock и связанные keyboard-flow ветки.

Из-за этого Telegram-версия накапливала второй и третий подъём поверх уже существующего.

## Текущее правило для Telegram

Ниже шапки Telegram-чат должен жить максимально близко к общей PWA/base-логике.

Что важно дальше:

- не добавлять отдельный Telegram keyboard lift без очень точного воспроизведения причины;
- не дублировать одни и те же inset/offset в CSS и JS одновременно;
- если composer снова начнёт ехать, сначала искать, кто именно меняет `keyboard-open`, `bottom`, `transform`, `pad`, `dock`, а не добавлять новый compensating fix;
- Telegram-specific поведение держать минимальным: шапка отдельно, чат ниже шапки как можно ближе к общей базе.

## Что важно помнить по процессу

- каждый отдельный фикс пушился отдельным коммитом;
- версия приложения поднималась по `+0.001`;
- за этот цикл версия выросла с `1.905` до `1.917`;
- этот документ фиксирует итог и главный урок, а не всю цепочку промежуточных гипотез.
