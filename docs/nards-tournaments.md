# Турниры по нардам

В гостиной рядом с нардами находятся два кубика «Турниры». Такая же кнопка
есть рядом с раскрытой доской. Обычный игрок видит общие турниры, администратор
также может создать турнир. Создание сразу открывает регистрацию для всех
авторизованных участников клуба. Турнир бесплатный, без операций с фишками.

Ссылка: `https://t.me/Poker_dvatuza_bot/DvaTuza?startapp=nards_tour_<CODE>`.
Веб-страница: `nards-tournaments.html?id=<CODE>`.

## Настройки и регламент

- Длинные или короткие нарды. В длинных также доступны бешеные и 6:1.
- От 2 до 64 участников; начало и закрытие регистрации задаются по Москве.
- Лимит победных очков отдельно для каждого раунда: от 1 до 25.
  Победа приносит 1, марс — 2, кокс — 3 очка. Допустимо превысить цель очками
  последней партии. При неполном наборе сохраняются цели последних раундов,
  включая заданную цель финала.
- Лимит хода 15/30/45/60 секунд. Как и в обычных клубных нардах, первый ход
  каждого игрока — 90 секунд. Отмена хода и ничьи в турнире выключены.
- Регистрация закрывается автоматически; админ может сформировать сетку раньше.
  После жеребьёвки запись и выход из списка запрещены. Пары распределяет сервер
  через Fisher–Yates и `crypto.randomInt`. Незанятые места дают проход без игры.
- Готовность можно подтвердить заранее. В назначенное время сервер начинает
  партию и сам определяет первого игрока и первый игровой бросок. Готовность
  не останавливает расписание: отсутствующим разыгрываются автоматические ходы.
- Третий пропуск подряд означает поражение во всём матче, независимо от его
  цели. Если ни один игрок матча не сделал ни одного ручного перемещения,
  исключаются оба; следующий соперник проходит без игры. Такой матч не создаёт
  случайную победу в обычном рейтинге.
- Следующая партия того же матча запускается автоматически через 5 секунд.
  Победитель матча сразу попадает в заранее созданную комнату следующего раунда.
  Когда определится второй игрок, от фактического окончания его предыдущего
  матча отсчитываются 3 минуты. Опросы страницы не продлевают этот перерыв.
- Вкладки «Моя игра», «Сетка», «Смотрю» сохраняют собственную игру в iframe.
  Из сетки можно смотреть любую партию, отдельно доступна пара будущего
  соперника. Зритель не занимает место и не может ходить. Игровые часы при
  просмотре продолжают идти.
- Оформление всех комнат — проверенный сервером снимок инвентаря создателя
  турнира. Личный инвентарь игроков не перезаписывается.
- Новых групповых или личных Telegram-рассылок турнир не отправляет.

## Реализация

`lib/nards-tournaments.js` — регламент, сетка и переходы. Результаты берутся
только из авторитетных комнат `board-games`, а не из тела клиентского запроса.
`lib/nards-tournament-runtime.js` — Redis, блокировка турнира, CAS комнат,
восстановление по сохранённым срокам. Создание идемпотентно по requestId;
регистрация дедуплицируется по каноническому аккаунту.

API: `/api/nards-tournaments`. Комнаты обслуживает существующий
`/api/board-games`; сервер запрещает преждевременные ходы, захват мест,
ручной реванш и ничьи. Переходы происходят при запросах и из уже настроенного
ежеминутного `/api/cron-billiards-wagers`, поэтому открытый браузер админа
не требуется. Просроченные ходы используют исходные серверные дедлайны.

Redis: `poker_app:nards-tournaments:v1:<CODE>`, индекс и короткие блокировки
в том же префиксе. Сам турнир хранится 60 дней, комнаты живут до семи дней
после планового старта. Сетка повторяет классы, соединительные линии, цвета
дорожек и расположение строк карты СНГ-баттла из
`styles-home-widget-modals.css`; этот существующий файл не изменяется.

Сборка: `npm run nards-tournaments:build` и сборка `scripts/board-games/main.mjs`
через esbuild. Общая `npm run build` включает готовые страницы и бандлы
в `public/`, ставит им версию релиза.

## Проверки

`tests/nards-tournaments.test.cjs` проверяет регламент, отсутствие участников,
очки, восстановление, переходы, неполный набор, 64 участника и реальные ходы
движка. `tests/nards-tournaments-access.test.cjs` — вход и ограничения API.
`tests/nards-tournaments-browser.cjs` — админ и четыре отдельных аккаунта,
регистрация → жеребьёвка → игра → ожидание → просмотр → возврат → финал.
Поддерживает `BROWSER=webkit` и `WIDTH=900`. Отдельный
`tests/nards-tournament-hall-browser.cjs` проверяет кубики и вход из гостиной.
Проверки используют локальные данные; реальные турниры и сообщения не создаются.
