# Снижение трафика Redis — 23 сентября 2026

## Изменения

- Обычный архив розыгрышей показывает только текущую и прошлую календарные недели по Москве. Старые записи остаются в Redis для адресных ссылок и финансового учёта; `archive-week` для более ранней недели возвращает ошибку без чтения истории.
- Архив и недельная выдача используют дневной индекс `raffle_stats_day:v3`. Индекс учитывает даты партий розыгрыша и действий с призами. Старый розыгрыш, приз которого выдали на текущей неделе, остаётся в недельной сумме.
- Первый запрос при отсутствии индекса делает разовое заполнение по истории. После маркера `raffle_stats_index:v3:ready` штатные запросы читают только даты нужного периода. Удалять старые данные для этой экономии не требуется.
- Публичный список игроков хранит URL аватаров в `avatar_public_urls:v1`, а не base64. Старые аватары переводятся в короткие URL при первом обновлении кеша; новые записи обновляют URL вместе с изображением.
- Профильные ID публичного списка читаются пакетами. Обычные аккаунты перестают делать отдельные Redis-запросы на каждую строку.
- Красная точка раздач сохраняет локальный результат для версии истории. При повторном открытии приложения с той же версией запрашивается только версия, без полного списка.

## Измерение после публикации

`REDIS_BANDWIDTH_AUDIT=1` включает лог `[redis-bandwidth-audit]` с контекстом, типами и числом команд, байтами HTTP-запроса и ответа Redis и временем. Для архива, недельных сумм и публичного списка логируются все вызовы; остальные вызовы сэмплируются на 1%. Ключи, значения и токены не логируются.

Сравнить 24–48 часов до/после при сопоставимом числе посетителей: команды и байты по контекстам `raffles.archive`, `raffles.currentWeekIssueTotals`, `player-crm.public-levels`, а также общий Cost Explorer Upstash. Размеры HTTP-ответов в логах — оценка приложения, не точное значение оплаченного bandwidth.

## Ограничения

- Первый запрос после публикации выполняет разовое заполнение индекса и может быть дорогим. Затем старые недели не читаются обычным архивным путём.
- Вкладка лидеров пока использует полную историческую выдачу при её открытии. Она не загружается при обычном открытии завершённых розыгрышей.
- Остальные источники нагрузки (пустой опрос чата, Daily Poker, ставки) требуют распределения команд и байтов по контекстам перед изменением механики: изменение частоты чата влияет на доставку сообщений, а агрегаты игр и ставок требуют проверки финансовой точности.
