У нард есть отдельный индекс турниров, которым ещё требуется обработка. Первый вызов переносит из старого индекса активные турниры и завершённые турниры с незакрытыми выплатами или уведомлениями. Новые записи обновляют индекс при сохранении. Параллельные опросы сетки используют последний снимок, пока другой запрос обновляет состояние. Игровые чаты читают сообщения по курсору. Last Longer хранит компактный кеш истории, привязанный к версии расчёта, и возвращает в меню активные персональные события и запрошенное событие.

## Замер в рабочей среде

После публикации выставить `REDIS_ROUTE_AUDIT_SAMPLE_RATE=0.01` на 24–48 часов. Лог `[redis-route-audit]` содержит маршрут, действие, долю выборки, количество Redis pipeline и отправленных команд, размеры HTTP-тел Redis, ошибки и время запроса. Поле `nards` отдельно показывает команды и байты с контекстом нард внутри общей фоновой задачи. Ключи Redis, данные, идентификаторы пользователей и токены в этот лог не попадают.

Сгруппировать логи по маршруту, действию и часу. Для оценки сумм разделить каждое наблюдение на его `sampleRate`. Сопоставить дни с похожим числом визитов и турниров и проверить итог в Upstash Cost Explorer. Команды внутри Lua и оплаченный трафик сверять с Upstash. Счётчик приложения измеряет отправленные REST-команды и размеры разобранных HTTP-тел, а не тарификацию провайдера. По завершении окна убрать переменную.

У розыгрышей, «Покера дня», достижений и CRM сначала сравнить частоту обращений и байты по маршрутам. Эти разделы уже используют индексы, агрегаты или кэши. Точечные изменения выбирать по замеру рабочих данных.
