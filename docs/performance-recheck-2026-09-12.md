# Повторный замер продакшена и стартовая сборка

Проверена опубликованная версия `90190202` на https://poker-app-ebon.vercel.app/. Новые изменения, описанные ниже, пока локальные.

## Продакшен

Четыре чистые гостевые сессии Chromium: 390×844, DPR 2, без браузерного кеша и Service Worker. Первые три — CPU ×4, 200 000 байт/с, задержка 100 мс; четвёртая — без искусственных ограничений. Реальные публичные API и CDN. Наблюдение заканчивается через 15 секунд после DOMContentLoaded, как в предыдущем продакшен-замере. Обычная стартовая аналитика приложения работает; формы и действия записи не выполнялись.

| Прогон | FCP, с | LCP, с | Завершённый HTTP-трафик, МБ |
|---|---:|---:|---:|
| Мобильный 1 | 6,30 | 7,04 | 2,76 |
| Мобильный 2 | 2,06 | 3,56 | 2,83 |
| Мобильный 3 | 5,68 | 6,32 | 2,76 |
| Без ограничений | 1,10 | 1,34 | 2,83 |

Медиана мобильного LCP — **6,32 с**, диапазон **3,56–7,04 с**. Это ещё медленная и нестабильная первая загрузка. В предыдущем продакшен-замере медиана была 7,51 с. Четыре сессии не заменяют статистику реальных пользователей, а эмуляция — физический телефон. Новое приложение не проверялось внутри реального Telegram WebView.

В быстром прогоне завершённый трафик уменьшился с 6,64 до 2,83 МБ — примерно на 57%. Мобильные итоги старого замера нельзя напрямую сравнивать по трафику: некоторые большие ответы тогда не успевали завершиться.

Подтверждено в каждом новом прогоне:

- Публичный список уровней передаёт примерно 20–21 КБ, сводка ставок — 0,8–0,9 КБ.
- Один запрос сводки ставок и один запрос домашнего блока розыгрышей.
- Нет гостевых запросов `friend-news` и `profile-wall` с отказом 401.
- Нет необработанных JavaScript-ошибок и горизонтального переполнения.

LCP-элемент — главный персонаж. В медленных прогонах `styles.css` завершался примерно через 5,3–5,6 с от навигации, `styles-home-overrides.css` — через 4,4–4,7 с, изображение — через 6,1–6,3 с. Это сетевые тайминги целого запроса, не время вычислений сервера. Облегчение API подтверждено, но оно не устранило ожидание блокирующих стилей и изображения.

## Изменения

1. Двенадцать последовательных файлов авторизации объединяются при сборке в один файл с хешем содержимого. Сохраняются порядок исполнения, глобальные объявления и положение относительно других скриптов. Исходники остаются раздельными. Проверка сборщика останавливает сборку при появлении промежуточного кода, top-level strict или зависимости от `document.currentScript`.
2. В опубликованном HTML будет **57 eager-скриптов вместо 68** при прежнем лимите 60. Inline CSS/JS сжимаются без удаления текста и пробелов HTML. HTML сборки — около **149 КБ** при прежнем лимите 154 624 байта. Проверка и отчёт теперь измеряют `public/index.html`, то есть реально отдаваемую сборку; исходный HTML остаётся удобным для редактирования.
3. Основной блокирующий CSS получает первый preload и высокий приоритет. Порядок применения CSS не меняется.
4. Рендерер домашнего блока SNG загружается без CSS закрытого диалога. Это убирает около 40 КБ gzip из ранней загрузки. Прямой вызов открытия, включая глубокие ссылки, ждёт CSS; ошибка показывает сообщение, следующая попытка повторяет загрузку.
5. Проверка шапки читает `styles-section-layout.css`, куда действительно перенесены общие правила. Исправлена и реальная раскладка: абсолютные административные кнопки вне главной перекрывали логотип и статус. Теперь кнопки занимают место в строке; на узких экранах полный набор с CRM переносится на вторую строку. Длинное имя и меню остаются видимыми.
6. PWA-кеш обновлён с v64 до v65.

## Контроль новых изменений

Две пары предыдущей и новой локальной сборки на одинаковом снимке публичных API: CPU ×4, 1,6 Мбит/с, 100 мс, 40 секунд наблюдения. Использован IPv6 loopback, чтобы приложение не включало автоматический доступ к отчётам для `localhost`/`127.0.0.1`. Записи API не отправлялись на сервер. Этот замер проверяет новые изменения и не является повторным продакшен-замером.

| Медиана | До | После |
|---|---:|---:|
| FCP | 2,80 с | 2,59 с |
| DOMContentLoaded | 8,29 с | 7,83 с |
| LCP | 4,10 с | 4,12 с |
| CLS | 0,00029 | 0,00029 |

**Убедительного ускорения LCP от этого этапа нет.** Уменьшились число стартовых запросов и время подготовки страницы, устранена загрузка CSS закрытого SNG, но считать проблему медленного первого экрана полностью решённой нельзя. Горизонтального переполнения и JS-ошибок нет. Статистику реальных телефонов и дальнейшее выделение минимального CSS первого экрана этот этап не заменяет.

Финальные пары находятся в `output/production-recheck-2026-09-11/guest-paired/`. Предварительный IPv4-прогон в корне каталога включает локальный административный режим и промежуточный CSS; он не используется для итогового сравнения.

## Бюджеты: что остаётся

| Показатель | Фактически, МиБ | Лимит, МиБ |
|---|---:|---:|
| Вся сборка без downloads | 131,15 | 105 |
| Основные и отложенные ресурсы | 42,67 | 30 |
| Текущий сезон | 38,64 | 36 |
| Архивные сезоны | 37,37 | 43 |

Эти превышения **не устранены**. Объём включает все экраны, иллюстрации, таблицы рейтинга, превью и изображения уведомлений. Он не равен трафику главной. Сборка содержит 842 основных, 2189 текущих сезонных и 2072 архивных файла ресурсов. Только папка с полноразмерными сжатыми таблицами рейтинга занимает около 41 МиБ. Байтовые дубликаты во всех ресурсах дают лишь около 0,82 МиБ потенциальной экономии — их удаления недостаточно для лимита 105.

Добавление auth bundle увеличивает полный каталог примерно на 0,16 МиБ: отдельные файлы оставлены для совместимости с прежними HTML-клиентами. При этом браузер новой версии запрашивает один bundle вместо этих двенадцати файлов.

Для выполнения общего бюджета понадобится отдельная работа с объёмом контента: перенос архивных ресурсов в отдельное хранилище либо подтверждённое удаление неиспользуемых вариантов. В проекте уже есть механизм `POKER_ARCHIVE_ASSET_BASE_URL`, но отдельное хранилище в этой работе не настраивалось. Массовое снижение качества таблиц и повышение лимитов не выполнялись.

Исправлена ошибка самого `assets:report`: раньше он показывал `violations: []`, проверяя только три стартовых лимита. Теперь он проверяет также полный размер, категории ресурсов и максимальный отдельный файл, возвращает ненулевой код при превышении. Общий `smoke` сохраняет две ошибки — полный объём и сезонные/основные бюджеты. Это не полностью зелёный release gate.
