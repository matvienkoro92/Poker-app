# 2026-05-03 UI, Scroll And CRM Worklog

Короткая фиксация текущих UX/технических решений, чтобы следующие правки не откатили уже найденные инварианты.

## Home Theme Visuals

- Главная в `gold` теме должна читатьcя как чистый графит/черный с мягкими золотыми бликами, без синей базы и без пыльно-коричневой бронзы.
- Фон шапки главной, фон под шапкой, `.card`, `.card__content`, `.card:has(home)::after` и `.home-welcome-outline` должны быть согласованы между собой. Если один из этих слоев остается старым, визуально появляется отдельная полоса или “грязный” оттенок.
- В `light` теме шапка главной и зона под ней должны оставаться в той же теплой светлой палитре, что и остальная главная. Кнопки `Устав`, `Радио`, `Тема` не должны получать темную капсулу.
- Блок `Следующий фриролл / Турнир дня` в `light` теме должен быть светлым: кремово-золотая панель, темный читаемый текст, мягкие границы и без черной доски из `gold` темы.

Основной файл: `styles-home-overrides.css`. Там намеренно лежат поздние overrides, потому что они перебивают базовые light/gold правила и legacy home tournament styles.

### Home Header Rollback Contract

После визуального эксперимента главной пользователь оставил только свежую верхнюю шапку. Все остальные крупные изменения первого экрана были откатаны.

- Шапка главной должна доходить до краев карточки, но внутренние элементы сохраняют собственные безопасные отступы.
- В закрепленной шапке не должно быть боковых внешних отступов, которые визуально сужают блок внутри card.
- У логотипа/названия клуба и у `Добро пожаловать!` не должно быть темной полосы от глобального button/background style.
- Стрелка справа от `Привет, Роман!` на главной скрывается CSS-ом, но DOM/control не удаляется: greeting/auth code все еще может использовать этот элемент в других состояниях.
- Если снова меняется home header, проверять оба состояния: обычная главная и закрепленная шапка после scroll.

Инвариант: правки home header должны быть локальны к главной и late overrides. Нельзя через общий reset ломать кнопки/modals на других экранах.

### Club Charter Modal Contrast

Последний видимый баг: в `gold` теме текст устава был темным на темной модалке, поэтому блоки `Поделиться`, `Скопировать` и заметка становились почти нечитаемыми.

- Для `.club-charter-modal__paper` в gold theme явно задается светлый текст.
- `kicker`, `title`, список правил и вложенные `p` получают отдельные gold-readable цвета.
- `.gazette-modal__share-btn` внутри club charter получает темный glass background, светло-золотой текст и border, потому что базовая кнопка наследовала неподходящий темный цвет.
- `.club-charter-modal__note` должна быть светлой заметкой на темном фоне, а не серым прямоугольником с темным текстом.

Инвариант: эти правила должны жить в позднем `styles-home-overrides.css` или в файле, который импортируется позже базовых modal/theme стилей. Если перенести их раньше, cascade снова может вернуть темный текст на темном фоне.

## Bottom Nav Icons

- Кнопки таббара по цветам и форме остаются в `styles-layout.css`; сами пиктограммы живут inline в `index.html`.
- Иконки должны выглядеть объемнее плоского outline: допустимы SVG `defs`, градиентные заливки, внутренние теневые слои (`bottom-nav__icon-depth`) и блики (`bottom-nav__icon-shine`).
- CSS для иконок:
  - `bottom-nav__icon svg` отвечает за общий размер, stroke и drop-shadow;
  - `bottom-nav__icon-fill--soft[style*="url"]` повышает видимость градиентных заливок;
  - active-state усиливает glow, но не должен менять размеры кнопки или двигать layout.
- Не добавлять декоративный текст в таббар и не увеличивать кнопки за счет иконок: проверять, что `npm run smoke:visual` не находит horizontal overflow.

## Long Screens And Scrollports

- Для экранов, которые должны скроллиться внутри панели, используем `.card__content` как scrollport, а не body-scroll.
- Сейчас в `app-navigation-scroll.js` `pokerGetPanelScrollCardContentEl()` включает:
  - `download`;
  - `hall-of-fame`;
  - `home`;
  - `cashout`;
  - `spring-rating`;
  - `raffles`;
  - `profile`;
  - `video-lessons`;
  - `player-crm`.
- `player-crm` не должен идти через общий `app-view-long-scroll`: ему нужен отдельный `app-view-player-crm-html-scroll` и CSS-режим в `styles-layout.css`, где `body/#app/.card` фиксируют высоту, а `.card__content` получает `overflow-y: auto`.
- При добавлении нового длинного view сначала решить, к какой модели он относится:
  - document/body long-scroll;
  - panel scroll через `.card__content`;
  - отдельный специализированный scrollport как `player-crm`.

## Cashout Images

- В `index.html` изображения менеджеров депозита лежат как `data-src`, а не сразу `src`, чтобы не грузить обе большие картинки на старте.
- `app-cashout.js:updateCashoutManager()` проставляет `src` только активному менеджеру и только когда открыт view `cashout`.
- `app-view-router.js:setView("cashout")` должен вызывать `updateCashoutManager()` перед/рядом с `initCashoutDepositForm()`, иначе картинка активного менеджера может не догрузиться после перехода.

## Player CRM

- `app-player-crm.js` теперь исходит из API-источника (`source: "api"`), а не из demo-массива.
- Demo players удалены из клиентского кода; сегменты строятся от реальных данных и выбранного периода.
- `daysLabel()` должен возвращать `—` для неизвестных/очень больших значений, чтобы CRM не показывал фейковую точность.
- `needsTouch` теперь приоритизирует реальные CRM-сигналы:
  - депозит есть, игры нет;
  - нет bot/push канала;
  - VIP;
  - давно не было CRM-касания.

## Raffles Performance

- В `lib/api-handlers/raffles.js` список розыгрышей читается пачкой через Redis pipeline, а не отдельным запросом на каждый id.
- Имена участников/победителей гидратируются пачкой через `hydrateRafflesParticipantNamesFromRedis()`.
- Write-back в Redis собирается в один набор команд по измененным raffle ids.
- На клиенте `app-raffles.js` счетчики завершенных розыгрышей обновляются сразу, но тяжелая разметка архива откладывается через timeout, если вкладка `completed` не видима. Это ускоряет показ активного розыгрыша.

## Chat Keyboard Debug

- `Keyboard Lab` / `poker_chat_keyboard_debug` не должен включаться в проде просто потому, что пользователь админ.
- `app-chat-lifecycle.js` разрешает keyboard debug только на `localhost`, `127.0.0.1`, пустом hostname или через query `chatKeyboardDebug=1`.
- Если окружение не разрешено, локальный флаг `poker_chat_keyboard_debug` очищается.
