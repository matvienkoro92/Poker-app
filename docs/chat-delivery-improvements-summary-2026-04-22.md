# Chat Delivery Improvements Summary

Дата: 2026-04-22

## Что было сделано

В этом цикле чат был ускорен без полной смены transport architecture.
Главная цель была такой:

- сократить latency отправки;
- приблизить доставку к realtime;
- снизить лишний bandwidth;
- улучшить UX доставки, статусов и списка диалогов.

## Реализованные улучшения

### 1. Async side effects после отправки сообщения

Из критического пути `POST /api/chat` вынесены блокирующие side effects:

- `Telegram notify`
- `web push notify`

Теперь ACK на отправку приходит после записи сообщения и обновления метаданных, а не после внешних уведомлений.

Эффект:

- быстрее отправка;
- меньше latency на `send ack`;
- меньше влияния внешних сервисов на chat UX.

### 2. Long-poll для активного треда

Добавлен long-poll path через `pollRev` и `waitForChange` для:

- `general`
- `DM`
- `group`

Эффект:

- новые сообщения в активном чате приходят заметно быстрее;
- меньше пустых polling-запросов;
- лучше perceived realtime без полного перехода на WebSocket.

### 3. Long-poll для списка диалогов

Добавлен long-poll path для `contactsMetaOnly`.

Эффект:

- unread и порядок диалогов обновляются живее;
- список диалогов меньше зависит от тупого интервала;
- снижен лишний фоновый трафик.

### 4. Perf trace и runtime telemetry

Добавлены trace-метки и client-side perf logging:

- `general-send-ack`
- `personal-send-ack`
- `general-delivery`
- `personal-delivery`
- `contacts-delivery`
- `push-incoming`
- `*-wait-timeout`

Эффект:

- можно видеть реальные узкие места;
- стало проще измерять latency и regressions.

### 5. Typing presence в личке

Добавлен `typing` path для DM:

- серверный TTL-ключ typing-presence;
- клиентский индикатор `печатает…`;
- авто-stop typing state.

Эффект:

- живее личные диалоги;
- лучше realtime-ощущение в активном DM.

### 6. Offline и reconnect UX

Добавлены базовые online/offline реакции:

- явный статус `Нет сети`;
- остановка long-poll при offline;
- восстановление polling/long-poll после `online`.

Эффект:

- меньше ложных зависаний;
- понятнее поведение чата при потере сети.

### 7. Read receipts и галочки статуса

Уточнена логика и UI статусов личных сообщений:

- `✓` серая: отправлено, но ещё не подтверждено как доставленное;
- `✓✓` серые: доставлено;
- `✓✓` зелёные: доставлено и прочитано.

Эффект:

- статусы стали понятнее и ближе к привычным мессенджерам.

### 8. Исправлен дубль optimistic message в общем чате

Убрана временная ситуация, когда у отправителя в `general` сообщение на мгновение показывалось дважды.

Эффект:

- чище отправка;
- меньше визуальных артефактов в общем чате.

### 9. Failed/retry state для сообщений

Добавлен `failed/retry` UX для своих сообщений:

- при неудачной отправке bubble не исчезает;
- сообщение помечается как `Не отправлено`;
- доступна кнопка `Повторить`.

Эффект:

- надёжнее UX при плохой сети;
- сообщение не “теряется” визуально.

### 10. Ускорение списка диалогов на клиенте

Список диалогов оптимизирован на стороне клиента:

- при обновлении `contacts` стараемся не делать полный rerender;
- существующие строки переиспользуются;
- порядок строк меняется через lightweight reorder;
- unread/online/name/pin обновляются точечно.

Эффект:

- список диалогов ощущается заметно живее;
- меньше лишней DOM-работы;
- лучше реакция на входящие и на перестановку диалогов вверх.

### 11. Убран один тяжёлый full-read path

Для `generalPin` добавлен tail-first поиск сообщения по `messageId` с fallback на полный проход.

Эффект:

- меньше лишнего чтения полной ленты;
- дешевле pin-action в типичном случае.

## Что это дало в сумме

По текущему состоянию чат уже:

- быстрее подтверждает отправку;
- быстрее показывает новые сообщения в активном треде;
- быстрее обновляет список диалогов;
- меньше расходует bandwidth в фоне;
- стабильнее ведёт себя на плохой сети.

## Что ещё не сделано

Чат всё ещё не стал полностью realtime-first.
Ключевой следующий слой:

- `SSE/WebSocket`
- `delta events`
- единый client-side store
- дальнейшая зачистка full-read/server-heavy path
