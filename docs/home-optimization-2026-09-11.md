# Оптимизация главной после измерения продакшена

Исправлены четыре подтверждённых источника нагрузки: большой публичный список уровней, повторные запросы ставок/розыгрышей, обращения гостя к закрытым лентам и тяжёлые изображения.

## Данные и запросы

- `publicLevels=1&avatarFormat=url` сохраняет поля и состав списка, но заменяет встроенные изображения короткими версионированными URL. На публичном снимке из 421 строки gzip уменьшился с 1 907 192 до 19 787 байт. Старый формат API поддерживается для совместимости.
- `/api/avatar?userId=…&format=image&v=…` отдаёт бинарное изображение с правильным MIME и кешем 5 минут. Это существующая возможность публичного чтения аватара через новый формат; авторизация собственных загрузок не менялась. Запрос изображения не создаёт и не переписывает аватар. Стандартные аватары перенаправляются на статические WebP.
- `/api/tournament-bet?mode=home` содержит банк, ставку, число участников и короткие сведения о завершённых публичных событиях. В снимке gzip составляет 685 байт. Список участников, рейтинг ставок, персональные события и административные данные загружаются при открытии полного окна. Две главные карточки используют один общий запрос с коротким кешем; изменение ставок инвалидирует его. Старый ответ в полёте не подменяет новый кеш.
- Счётчик розыгрышей и сундук турнира делят запрос `homeBonus=1`. Кеш учитывает авторизацию, защищён от запоздалого ответа предыдущего аккаунта и поддерживает принудительное обновление.
- Гостю не отправляются `friend-news` и `profile-wall`. После появления Telegram/PWA/VK-авторизации ленты снова доступны. Одинаковые запросы достижений голосования используют один ключ кеша. Разные запросы общей суммы выигрышей и списка новостей остаются разными: они возвращают разные данные.
- Удаляются два устаревших sessionStorage-кеша публичных списков с встроенными изображениями.

## Изображения

38 используемых изображений: **3 098 475 → 1 469 090 байт**, экономия **1 629 385 байт, 52,6%**. Это сумма файлов, а не размер всей установленной сборки и не обещание одинаковой экономии на каждом экране.

Созданы варианты WebP с размерами под отображение, качеством 84 и сохранением прозрачности. Оптимизированы основной персонаж, три карточки клуба, фон, сцены турнира, две картинки новостей, персонаж рейтинга, логотип, игровые карточки и стандартные аватары. Исходники сохранены. Три кандидата, у которых повторное кодирование увеличивало размер, оставлены в исходном виде.

Три слоя турнира используются только через CSS-маски/обрезку. Невидимые пиксели удалены с сохранением исходной системы координат и запасом вокруг видимой области:

| Слой | Было | Стало |
|---|---:|---:|
| Накладка названия на ведре | 206 824 Б | 12 738 Б |
| Исправление края стола | 243 244 Б | 17 994 Б |

Границы этих слоёв заданы в `scripts/generate-home-responsive-art.js` и должны оставаться согласованными с масками `styles-home-tournament-scene.css`. При изменении масок нужно проверить границы повторно. Размеры top-3 рейтинга через CSS не изменялись.

Дополнительно фоновые слои турнира включаются за 300 px до появления блока на экране. При отсутствии IntersectionObserver применяется обычная загрузка. Стандартные изображения и данные доступны и при повторном открытии секций.

## Парный замер

Чистый Chromium, 390×844, DPR 2, CPU ×4, 200 000 байт/с, задержка 100 мс, кеш браузера выключен, Service Worker блокирован. Две загрузки исходной сборки `ca5d66d9` и две новой. Наблюдение до 40 секунд от начала навигации, без прокрутки. Статика обслуживалась локально с gzip; публичные API были получены один раз и повторно использованы в памяти. Новый JSON сформирован теми же функциями проекции, что используются в серверном коде. POST не пересылались в продакшен. Шрифты и Telegram SDK загружались извне.

| Показатель | До | После |
|---|---:|---:|
| Средний завершённый HTTP-трафик | 7,20 МБ | 2,75 МБ |
| Медиана FCP | 4,30 с | 2,19 с |
| Медиана LCP | 5,93 с | 3,54 с |
| Запросы полной информации о ставках на старте | 2 | 0 |
| Запрос короткой сводки ставок | 0 | 1 |

Трафик уменьшился примерно на **62%**. Встроенные data:image не считаются повторно как сетевой трафик. После этих прогонов дополнительно объединён запрос розыгрышей; финальная проверка на 1280 px подтверждает один `homeBonus` вместо двух. Она также подтверждает отсутствие закрытых лент в гостевой загрузке, загрузку отдельных аватаров и полных ставок после открытия окна.

Это контрольное сравнение локальных сборок на одинаковых данных, не замер новой версии на опубликованном сайте и не физический телефон. Две пары не заменяют статистику реальных пользователей. DOMContentLoaded не означает готовность всех действий. Публичные данные к моменту проверки изменились: размеры ответов ставок отличаются от предыдущего замера продакшена.

## Проверки и ограничения

- 279 модульных тестов: проходят, включая бинарные аватары, суммы/победителей, разделение запросов, повтор после ошибки, смену аккаунта и гостевые ленты.
- Контрактные проверки: проходят. Сборка проходит. Синтаксис: 479 JS и 85 CSS; последующие изменённые JS проверены отдельно.
- Мобильное сравнение: без необработанных JS-ошибок и горизонтального переполнения. CLS около 0,0023.
- PWA v63 → v64: проходит, черновик сохраняется до применения обновления, новый CSS загружается.
- Браузерная проверка CSS-манифеста: стили новостей не грузятся на старте, повтор после 503 проходит, повторное открытие использует загруженный CSS, общая раскладка профиля загружается один раз.
- Визуальные снимки и журналы находятся в `output/home-optimization-2026-09-11/`.
- Общий `npm run smoke` не полностью зелёный. В исходной версии отдельно воспроизведены нарушения старых бюджетов HTML/числа стартовых скриптов, общего размера/категорий ресурсов и строковой проверки CSS шапки. Необъявленные глобальные зависимости и владение четырьмя CSS-файлами исправлены. Остальные старые проверки не отключались и лимиты не повышались.
- Размер всей сборки без APK: 131,57 → 130,99 МиБ при лимите 105 МиБ; core-ресурсы 43,25 → 42,67 МиБ при лимите 30; текущий сезон 38,64 МиБ при лимите 36. Эти цифры включают ресурсы всех экранов, архивы и совместимые исходные файлы; они не равны стартовому трафику. Исходный HTML имел 67 eager-скриптов при лимите 60; новый — 68, включая общий загрузчик данных.

Изменения пока локальные, публикация в этот этап не входит.

Временная копия старой сборки удалена после сравнения. Для повторения парного скрипта её нужно восстановить из `ca5d66d9` в `output/home-optimization-2026-09-11/before-public`; снимки, размеры и журналы сохранены.
