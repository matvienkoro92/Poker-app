# Бильярдная Two Aces

Проход в гараже виллы (`data-house-passage`) открывает `billiards-play.html` в полноэкранном диалоге. «Вилла» закрывает его и сохраняет текущую комнату, персонажа и транспорт. Iframe загружает собственный bundle только при входе; основное приложение не получает дополнительную 3D-сцену при запуске.

Комната использует отделку виллы, бордовые кресла и растения из того же каталога. Окна выходят на заднюю террасу: бассейн непосредственно перед ними, океан за бассейном. Это соответствует расположению бассейна в `scripts/city-game/villa.mjs`. «К столу» включает верхний игровой ракурс; светильники скрываются, чтобы не перекрывать шары.

## Онлайн

Один пользователь создаёт комнату, другой входит по десятисимвольному коду из своего аккаунта. Код генерируется сервером из криптографических случайных байтов. HTTPS API `/api/billiards` использует действующую авторизацию приложения и Redis; игровые комнаты живут два часа. Третий участник не может войти или прочитать состояние. Призы, рейтинги и данные гаража не изменяются.

Сервер рассчитывает физику удара общим детерминированным движком с шагом 1/120 с. Клиенты получают одинаковое начальное состояние, удар, время начала, длительность и подтверждённый результат. Они проигрывают движение локально, затем принимают результат сервера. Ходы привязаны к участнику и ревизии. CAS в Redis предотвращает повторный удар и одновременное занятие второго места. Во время движения следующий ход не принимается. Просроченные ответы не откатывают состояние. После временного отключения клиент продолжает опрос; повторный вход по коду восстанавливает партию.

Запросы ограничены: 130 опросов и 25 действий в минуту на аккаунт. Опрос — раз в 800 мс. Комната не требует открытого приложения создателя, прямого WebRTC или стороннего сервиса сигнализации. Требуются действующие настройки Redis в окружении приложения. Изначальный WebRTC-вариант заменён: даже локальный RTC-тест в среде разработки не устанавливал UDP-соединение.

## Правила

Клубная упрощённая «восьмёрка»: группы назначаются по первому забитому шару без фола; свой забитый шар оставляет ход; забитый биток, отсутствие контакта или первое касание чужой группы дают сопернику биток с руки. Восьмёрка разрешена после очистки своей группы отдельным ударом, ранняя восьмёрка или восьмёрка с фолом — поражение. Луза не заказывается; обязательного касания борта после контакта нет. Правила доступны в игре.

## Проверка

- `npm run billiards:build` — отдельный bundle.
- `node --test tests/billiards.test.mjs tests/billiards-service.test.cjs` — физика, фолы, восьмёрка, очередность, устаревший повтор, атомарное занятие места, истечение комнаты.
- `node tests/billiards-browser.cjs` — два изолированных браузерных аккаунта, настоящие HTTP-запросы к тому же игровому сервису с тестовым хранилищем, общий удар и результат, восстановление после offline/reload. Тест не обращается к production Redis и не подменяет физику/результат на клиенте.
- `node tests/billiards-entry.cjs` — переход из гаража и возврат в тот же гараж.
- Снимки: `output/billiards/{room-mobile,room-desktop,table-mobile}.png`.

Публикация серверного маршрута и статических файлов требуется вместе. Локальные изменения не публикуются автоматически.
