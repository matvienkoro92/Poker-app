## Найденные ошибки и исправления

| Проблема | Последствие | Исправление |
| --- | --- | --- |
| Ранний `return` в `consumePendingStreamsWatchRoom` | Обычный вход не находил запущенный эфир | Один отложенный поиск; повторный вызов роутером не дублирует его |
| Ответы запросов и диалог захвата приходят после выхода | Плеер/захват могли снова включаться вне раздела | Проверки поколения запроса, отмена таймеров, остановка поздно полученных треков |
| Ошибка Egress переключала `delayed` на `instant` | Выбранная задержка исчезала | Запуск останавливается, режим не меняется |
| Недостаточный DVR-буфер не мешал воспроизведению | Вместо двух минут показывались последние секунды | Видео скрыто и приостановлено до готовности буфера; автоматическое продолжение после восстановления |
| Запасной iframe обходил контроль задержки | Показывался обычный Cloudflare-плеер | Этот fallback отключён; при исчерпании попыток предлагается обновить эфир |
| После ENDLIST неподвижная граница DVR перематывала видео назад | Последние минуты эфира нельзя было досмотреть | Для HLS.js после ENDLIST завершающая часть освобождается по времени; для native HLS обрабатывается переход бесконечной длительности в конечную |
| `adaptiveStream: true` вместе с ручным `MediaStream` | LiveKit мог не отправлять видео | Адаптивная подписка отключена для текущего способа подключения треков |
| `disconnect()` по умолчанию останавливает локальные треки | Повторная публикация уже завершённого экрана | Ожидание `disconnect(false)` перед повторным подключением; источником управляет runtime |
| Завершение любого трека останавливало весь эфир | Отключение микрофона закрывало показ экрана | Автоостановка привязана к видеотреку |
| Promises публикации обрабатывались последовательно, хотя запускались вместе | Риск необработанного отказа одного из треков | `Promise.all` |
| Ошибка сохранения текущего эфира оставляла трансляцию без рабочего входа для зрителей | Ведущий видел успех, зрители не находили эфир | Резервирование обязательно до публикации; зрителям эфир объявляется после запуска; ошибка завершает запуск |
| Глобальная запись эфира жила шесть часов без heartbeat | Закрытый браузер оставлял «активный» эфир | Сессия запуска, heartbeat раз в 30 секунд, срок активности 150 секунд |
| Stop/start выполнялись без проверки владельца и атомарности | Старый или другой запуск мог стереть новый эфир | Владелец + секрет сессии, Redis compare-and-set, последовательные клиентские записи |
| Токен зрителя открывал исходную комнату задержанного эфира | Обход задержки через прямой LiveKit | Задержанные источники имеют отдельные комнаты с идентификатором сессии; токены зрителей туда не выдаются |
| Повторный Egress старт не проверял действующий экспорт | Возможны дубли экспорта | Проверка `ListEgress`, повторное использование, распределённая блокировка создания |
| ID экспорта не проверялся при остановке | Можно было указать экспорт другой комнаты | Проверка комнаты и сессии по `ListEgress` перед `StopEgress` |
| Поздний ответ старта экспорта после stop | Экспорт мог продолжаться без ведущего | Повторная серверная проверка сессии и остановка позднего экспорта |
| Состояние Egress больше не проверялось после запуска | Завершившийся мост считался рабочим | Проверка/восстановление моста при heartbeat; при длительном отказе эфир останавливается |
| Конфигурация с полным RTMPS destination считалась неполной | Ложный `egressConfigured: false` | Учитывается полный destination URL |

## Что задержка действительно гарантирует

Штатный плеер ждёт DVR-буфер и не переключается на прямой эфир при сбое. Обычный зрительский токен не открывает задержанный исходник LiveKit.

Однако Cloudflare HLS остаётся публичным, и URL доступен через API конфигурации. Пользователь, намеренно открывший исходный HLS другим плеером, может обойти клиентскую задержку. Поэтому обещание «против подсматривания» заменено точным описанием. Строгая защита требует задерживать сам выдаваемый сервером поток и закрывать доступ к исходному live-потоку; одними настройками текущего JavaScript это не решается.

## Установка

Серверная и клиентская части устанавливаются вместе. Для серверных функций нужен общий Redis: там хранятся активная сессия и блокировка экспорта. Режим без Redis предназначен только для локальной работы в одном процессе. Ведущим потребуется перезагрузить старые открытые страницы: прежний клиент не передаёт идентификатор сессии. URL скрипта обновлён отдельно для сброса браузерного кэша.

## Документация SDK

- [LiveKit RemoteVideoTrack](https://docs.livekit.io/reference/client-sdk-js/classes/RemoteVideoTrack.html): при adaptiveStream нужен `track.attach()`.
- [LiveKit Room](https://docs.livekit.io/reference/client-sdk-js/classes/Room.html): `disconnect(stopTracks)` по умолчанию останавливает треки.
- [LiveKit Egress API](https://docs.livekit.io/reference/other/egress/api/): состояния экспорта, `ListEgress`, `StopEgress`, права `roomRecord`.
