# Chat Work Summary — 2026-04-18

## Цель работы

Исходная задача была двойная:

1. оптимизировать чаты так, чтобы они потребляли меньше `bandwidth`
2. сделать так, чтобы новые сообщения и push-уведомления доходили и открывались максимально быстро

По ходу работы задача разделилась на три больших блока:

1. оптимизация трафика и рендеринга чатов
2. стабилизация push-подписок и доставки push
3. открытие нужной лички по клику на push в PWA

---

## Что было сделано по оптимизации чатов

### 1. Снижение bandwidth

Были внедрены основные оптимизации сетевого слоя:

- облегчённый `contacts meta-only` path
- адресный refetch после push вместо широкого каскада запросов
- `pollRev/notModified` для облегчённого `contacts`
- ранний серверный `contacts-meta` short path
- server-side fast-tail path для diff-запросов `general` и `personal`

Практический результат:

- уменьшился payload фоновых запросов
- сократилось число лишних refetch
- обновление списка диалогов стало дешевле по сети

### 2. Оптимизация UI и рендера

Были сделаны:

- `append-path` для новых сообщений
- `prepend-path` для догрузки истории
- частичные обновления вместо полного `rerender` всей ленты
- быстрый lookup сообщений для `edit/delete/reactions`
- клиентские точечные патчи для части операций

Практический результат:

- чат стал живее на частых обновлениях
- уменьшились лишние перерисовки
- улучшилось ощущение скорости при активной переписке

### 3. Серверные оптимизации работы с сообщениями

Были добавлены:

- индекс сообщений по треду
- быстрый lookup через индекс
- backfill индекса для старых сообщений

Практический результат:

- снизилась стоимость операций `edit/delete/reaction`
- уменьшилась необходимость читать весь тред

Практический результат:

## Что было сделано по открытию чата из push

Это оказался самый проблемный и до конца не закрытый участок.

Мы последовательно проверили и пробовали:

- deep-link открытие через `?startapp=club_chat_dm&with=...`
- открытие через `postMessage` из `sw.js`
- хранение и replay push target
- отказ от replay, чтобы не ломать обычный старт PWA
- прямой `openConv` path
- retry после `focus()`
- retry после `auth verified`
- retry после `initChat()`
- анти-rollback при возврате в список чатов
- отдельный direct conversation shell для push-DM
- визуальный debug overlay по шагам цепочки push-open

### Что удалось установить точно

По debug overlay выяснилось:

- `push click` реально доходит до клиента
- `with=<peer>` не теряется полностью
- код реально доходит до шагов `pending-dm` и `openConv-direct`
- при этом UI всё равно остаётся на экране списка чатов

То есть проблема не в том, что `openUrl` вообще не приходит. Проблема глубже: на cold-open PWA разговорный экран не закрепляется, хотя логика пытается его открыть.

- при открытом приложении ранее иногда не происходило ничего либо открывался не тот экран
